# Banner collector map

Maps every dependency banner defined in `buildout/wireframes/parts/14-deps-data.js` (`EVDEP_DEFS`) to the Go backend code that actually detects the condition it describes, with the copy-only remediation text already shown to the user and the wireframe cards that depend on each banner (`EVDEP_MAP`). All 9 ids present in `EVDEP_DEFS` are covered; no other ids exist in that object.

## 2. Gaps

Four of the nine banners have no detector in the Go backend today:

- **`qswaits`** — The lane's Query Store options query (`qLaneQSOptions`, `internal/dbhealth/lane_sql.go:26`) would need an added `wait_stats_capture_mode` column, and `evalQSOptions` (`lane_sql.go:360`) / `qsOptions` would need a field for it, plus a check distinct from the existing on/off check so a database with Query Store **on** but wait-stats capture **off** can still raise this (soft) banner instead of staying silent.
- **`systemhealth`** — Needs a new read-only query against `sys.dm_xe_sessions` (optionally joined to `sys.dm_xe_session_targets`) filtered to `name = 'system_health'`: a missing row (or a row showing the session stopped) is the condition. No such query exists under `internal/dbhealth` today; only the file-export detector in `internal/discover/detect_sql.go:220` touches `system_health` at all, and it only looks at `.xel` files already on disk.
- **`oplogread`** — Needs a read-only probe against the `local` database, e.g. a bounded `find` against `local.oplog.rs` (mirroring the `system.profile` probes already in `lane_mongo.go`), wired through the same `classifyMongo` (`mongo.go:81`) permission classification so a denial surfaces this banner instead of a generic failure. This would also require loosening the lane comment's current "standalone server, no replication check" assumption (`lane_mongo.go:10-11`).
- **`perfaccess`** — Needs the Windows PDH layer (`extras_windows.go:55`) to inspect the actual PDH/Win32 status code (e.g. access-denied vs. no-such-counter) and surface it as a new typed `ReadError` kind, and `errState` (`state.go:179`) would need a new `case` for that kind so it reports a distinct state/reason instead of folding into generic `SUnreachable`.

## 4. Rules

Read-only, no SQL probe, copyable text only — observed directly in the code, not inferred:

- Every remediation script is built as a plain Go string (`SQLGrantScript`, `internal/dbhealth/grants.go:121`; `MongoGrantScript`, `grants.go:165`; `QueryStoreOnScript`-style text inline in `lane_sql.go:83-87`; `MongoProfilerGuide.SwitchOn`/`SwitchOff`, `grants.go:200-202`) and returned as `GrantFix.Script` / `ProfilerGuide` fields for the UI to display. No call site passes any of these strings to a query/command execution function.
- Each of these structs carries an explicit disclaimer sentence in `EVDEP_DEFS`'s `note` field or in the Go-side guide text itself (e.g. `grants.go:197`: "Unravis only reads and never runs it... Unravis never runs it"), repeated per banner in `14-deps-data.js`.
- The Mongo side additionally enforces this at the protocol layer: `ReadOnlyCommand` (`internal/dbhealth/mongo.go:22`) accepts only `serverStatus`, `currentOp`, `replSetGetStatus`, `dbStats`, `collStats`, `listIndexes`, a `profile` command with value `-1` (read the level, never set it), or a `find` on `system.profile`, and explicitly rejects any command containing `$where`, `$function`, `$accumulator`, `$out`, or `$merge` (`mongo.go:44-47`). Every Mongo check in `lane_mongo.go` and `mongo.go` goes through this allowlist before reaching the server.
- The SQL side has no equivalent single allowlist function in the files read for this task; its read-only guarantee is `unverified` beyond the fact that every query constant found (`qLaneServer`, `qLaneQSOptions`, `qWaits`, `qQSState`, etc.) is a `SELECT`.
