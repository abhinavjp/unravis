Unravis, the whole workflow

From an empty computer to a closed case: set up saved connections and a Blackbox, create a case, add sources, investigate (Guided analysis or Manual tools), then close, archive, free or erase it. 139 screens, drawn with the real Unravis styles and wording on dummy data from one invented incident: logins became slow at 10:42 UTC on 26 Oct 2026. The story clock reads about 11:05 UTC on 26 Oct; screens about a closed, archived or erased case are marked as later (27 Oct).

Read-only. Unravis reads your servers and never changes them. On this PC it makes these changes to its own Blackbox, each when you press its button: Install adds the Blackbox service, Start starts it, Apply settings restarts it, Stop stops it, Remove uninstalls it, and Delete the recordings too deletes the recordings folder. Windows asks for administrator approval for the service changes. Snapshot copies the recordings into one folder. Nothing is done to another server. Anything that would change a server (a permission, a setting) is a script you copy and run yourself. Passwords are saved sealed on this PC with Windows data protection and are never shown again.

Terms. An audit record is one logged API call in MongoDB. A route is the URL path of an API, such as /api/auth/login. A tier is one layer a call passes through: IIS (web server), the API process, SQL Server, MongoDB. Time is split as A (API code) + C (calls to databases) = D, the duration Unravis measures; P is time in filters before the action, outside D; O is what is left of the IIS time: IIS time-taken − D − P (queueing and network); W is the time one call spends in a tier (waiting and working).

Sources and words. A source is one place Unravis reads from: a SQL Server, a MongoDB, a Blackbox or files. A Blackbox is a small recorder service on a server that writes CPU, memory, disk and log facts every 15 s, so the evidence exists before anyone investigates. It can optionally also record SQL Server activity (the database probe, off by default, ticked per Blackbox). A Blackbox on another server cannot be found from here: give its folder, network share or URL and port. The incident window is the period being explained and the reference window is the normal period it is compared with. Onset t0 is the minute things first went wrong. A source is shown as Ready, Partly ready, Cannot test yet (the check could not run: missing source or permission, never a pass) or Failed. A check is one of the four SQL cards: Health, Query Store, Blocked sessions, Jobs and error log. Works, Failed and Not tested are used only for a connection test; Running and Running, late only for a Blackbox.

Suspects. Colours say how much the data supports a suspect: red most likely, orange likely, green ruled out by the data we have, grey not sure (not enough data; grey is not a pass). The letter in a suspect id says where it lives: S = SQL, H = host, M = Mongo, L = load, C = code change. These ids are not screen numbers. The boxes called In a nutshell give the same idea in everyday words.

Every screen has a strip: Do (what you do here), Answers (the question it settles) and Next (where it leads, as links). A Step is one of the analysis steps 0 to 10, a Part is one page of a set-up wizard (Part 1 of 4), and a Screen is one drawing on this page, found by its link or the number in its heading. The top bar of each screen is the app's own: Home (cases, Blackbox, Connections) is separate from the case bar, which always shows the case code, its state, its mode and its tabs. Live mode in the top bar means you are looking at your real servers and data, read-only. Lock locks Unravis, so the key is asked for again (Screen 4). Words and symbols are in the Reading guide (Screen 74); how to switch on what a check needs is Screen 34. Data shown is invented. Screens are static; drop-downs are drawn as buttons, and the Theme and Width switches check both themes and a phone.
