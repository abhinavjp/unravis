### New `web/scripts/check-dist.cjs` (about 110 lines, plain Node, no dependencies)

Exports and CLI:

```js
const ROOTS = ['web/dist', 'cmd/unravis-setup/ui', 'cmd/unravis-lite/ui'];
function checkDist({ repo, roots = ROOTS }) -> {
  missing: string[],   // committed at HEAD, absent on disk
  extra: string[],     // on disk, not committed (untracked OR ignored: it walks the disk, not git status)
  changed: string[],   // on disk and committed, blob id differs
  eolOnly: string[],   // subset of changed: equal after CRLF->LF (hint only)
  notFile: string[],   // on disk but a symlink or other non-regular entry
  noIndex: string[],   // roots with no index.html committed at HEAD
  ok: boolean
}
```

Algorithm (CHECKED as a prototype here; 0.07 s for 91 files):

1. `git rev-parse --show-object-format` must print `sha1`, else throw (exit 2).
2. For each root: `git ls-tree -r -z --full-tree HEAD -- <root>` gives `path -> blob id`. The root must contain `<root>/index.html`, else add the root to `noIndex`.
3. Walk the root on disk with `fs.readdirSync(..., {withFileTypes:true})`, recursive, dotfiles included. A directory entry that is neither file nor directory goes to `notFile`.
4. For each disk file compute the git blob id in Node: `sha1("blob " + size + "\0" + bytes)`. No text filter is involved, so `core.autocrlf` cannot hide a difference. (`git diff --exit-code` and `git status` do hide it: CHECKED, with `autocrlf=true` a CRLF file shows `M` in `git status --porcelain` before refresh and `git diff --quiet` reports clean.)
5. Not on `HEAD` -> `extra`. Blob differs -> `changed`; then read the committed blob with `git cat-file blob <id>` (only for changed files) and if both sides are equal after CRLF->LF, also add to `eolOnly`.
6. Committed paths never seen on disk -> `missing`.
7. File mode is ignored (Windows has no exec bit).

CLI: `node scripts/check-dist.cjs [--repo <dir>]`. Default repo = `git rev-parse --show-toplevel` from the current directory. Exit 0 ok, 1 differences, 2 cannot run (no git, not a repo, not sha1). Output on failure (first line is the instruction; lists capped at 20 each with "and N more"):

```
::error::The built web files differ from what is committed. Run `npm run build` in `web` and commit the three folders: web/dist, cmd/unravis-setup/ui, cmd/unravis-lite/ui.
changed (2): ...
extra (1): ...
missing (0)
only line endings differ (1): ... (check .gitattributes)
```

The `::error::` prefix is printed only when `GITHUB_ACTIONS` is set; otherwise the same sentence without it.

## 1.5 Security

- Read-only: reads the working tree and runs `git ls-tree` and `git cat-file` (fixed arguments, no shell, `spawnSync` with an argument array). No network, no secrets, no write. Fits `permissions: contents: read`.
- Paths come from `git ls-tree -z` and the disk walk, never from user text; they are only printed. Strip control characters from names before printing (so a crafted file name cannot forge a `::error::` annotation).
- Does not execute any built file.
- A lockfile or dependency change can legitimately change output; reviewers must read `web/package-lock.json` diffs. The gate does not replace that.
- The gate makes it harder to ship a dist that does not match source (a tampered dist in a PR fails unless the source produces it). It does not stop a malicious source change.

# PART 2: BL-016 Query Store OFF history

## 2.1 Behaviour

Today (`lane_sql.go:706`): OFF, ERROR, empty state or no options row all return "Cannot test yet" with the switch-on script, and no history query runs.

New behaviour by options row:

| Options row | Action | Check state | Saved |
|---|---|---|---|
| ON / READ_WRITE | unchanged | unchanged | unchanged |
| READ_ONLY | unchanged | unchanged | unchanged |
| OFF | run the range query (1 read). No rows or NULL first -> today's exact message and fix script. Else read stats and intervals only in slices that touch [first, last], evaluate with the OFF rules below | Ready or Cannot test yet (see wording) | `QueryStore{State: off, FirstData, LastData, IntervalMinutes}` and `Series` when intervals came back |
| ERROR | no history read, no script | Cannot test yet | `State: unknown` |

| options query fails | unchanged (`failed`, state `denied` or `unknown`) | unchanged | unchanged |

OFF rules (all INFERRED from the research and the groom; live engine behaviour NOT VERIFIED, see 2.9):
- Keep the asked windows. Never move them to the retained range. Read only slices that overlap [first, last]. Draw only buckets that exist.
- "Coverage" = the newest kept block starts at or after the incident end: `!last.Before(req.Incident.End)`. It is on block start, not block end, so a possibly partial final block (OFF (FORCED) skips the last flush) never counts as covering.
- Without coverage, drop every `No` answer (D3, D14, D15). A `Yes` stays. A plan regression found in earlier buckets is still a yes. Reason: OFF may have started mid-incident, and a missing change is not evidence of none (same idea as the existing `truncated` rule).
- With coverage, answers follow the normal rules.
- Never say when Query Store was switched off. `sys.database_query_store_options` has no such time. Only observed block times are shown, labelled as block starts.
- Never read `sys.query_store_query_text`, never write, never run `ALTER`.

  - `dbState` switch: `case 'offkept'` returns `{ key, source: T.dbSrcOffKept, message: T.dbMsgOffKept(from, to), short: T.dbShortOffKept, shape, measure }`. `from` = stamp of `queryStore.firstData`; `to` = stamp of `queryStore.lastData` plus the block minutes when the block length is known (`input.blockSeconds`), else the `lastData` stamp; each is `null` when absent. A stamp is `fmt.date(iso) + ', ' + fmt.time(iso)`.
  - `case 'off'`: message is `T.dbMsgOffOutside(from, to)` when both `firstData` and `lastData` exist, else the unchanged `T.dbMsgOff`.
- `src/lib/drill/drillCopy.ts` (new keys; lint rules apply, and each function must be added to `SAMPLE` and to the `fns` list in `drillCopyEntries`, or `lint entries ... cover every key` fails):
  - `dbSrcOffKept: 'Query Store (off), kept history'`
  - `dbMsgOffKept: (from, to) => from && to ? \`Query Store is off. The blocks show the history it kept, from ${from} to ${to}. The time outside that range is unknown, not zero.\` : 'Query Store is off. The blocks show history saved earlier. The time outside it is unknown, not zero.'`
  - `dbMsgOffOutside: (from, to) => \`Query Store is off. It kept history from ${from} to ${to}, but none of it is for this time. The database owner can switch it on; Unravis never does.\``
  - `dbShortOffKept: 'Kept history, Query Store is off'`
  CHECKED: these four strings pass `lintScreenStrings` with `deck.terms` (run here: no findings). Re-run in the PR.
- `src/components/SlowCallScreen.svelte`: no change. `savedDay` is the newest saved day (`newestDay`), `queryStore` is passed through already (`:242`).

Wording note for the no-times variant: when the newest day is OFF but has no `lastData`, the drawn blocks can come from an earlier saved day that was read while Query Store was on. The sentence "history saved earlier" is true for both cases and makes no claim about when it was off.

## 2.6 Security

- Fixed query texts only; the only inserted values are datetime literals from `sqlOffsetLit`, built from the request windows. `clipBatches` only drops spans, it never rewrites a bound, so a value read from the database (`first`, `last`) never enters a query text.
- Read only: no `ALTER`, no `INSERT/UPDATE/DELETE/DROP`, no `EXEC` in the QS queries. The query text view `sys.query_store_query_text` is not read (it needs a server-level grant). A test greps the constants (2.8).
- No wider grant than today. No secret handling change. Summary strings carry only database times and fixed words; no database name beyond what the existing script already prints.
- Unravis still never switches Query Store on. The OFF-no-history message keeps the owner-run script.
- Data leak check: `LastData` is a time. Reports are saved in the case store as today.
- Abuse: a hostile server can return any first/last; effect is bounded by `laneBatches` (slices of the windows the user asked) and `laneQSMaxRows`. No new loop over server-supplied counts.

## 2.7 Footprint

- ON, READ_ONLY, ERROR, no row: no change (ERROR and no row save nothing; they used to also save nothing).
- OFF, no history: +1 query (tiny aggregate over the interval table) per lane run, 20 s limit.
- OFF with history: the same number of read queries as an ON database for the overlapping slices (2 per 72 h slice, 60 s limit each, top 3000 rows), usually fewer because empty slices are skipped. Runs on the owner's SQL Server on demand, not in the Blackbox.
- Memory: same row cap as today. No new network. Saved report: same series cap plus 1 time field.
- Web: 4 strings and one branch. Dist grows by well under 1 KB.
