# Slice card: P14a plain-language help

Sources: roadmap §5.3 (card fields), §8.14 (P14), §6.6 (wordings), §5.2 and §5.4. Status: planned, not built.

**Slice:** P14a, plain-language help (roadmap §8.14 parts 2, 3, 5): the copy deck, "What does this mean?" hints, the glossary and plain results. First release of P14. Out of scope: P14b (first-run tour, guided practice case; parts 1 and 4).

**Preconditions:** None external: local copy and demo data only (§5.2). T0 items: none required. Earlier slices: none. Status: met. Must follow the §6.6 wordings. Proceeds even if T0.1 cannot be done (§5.2).

**Incident question:** Exempt (usability slice). Purpose (§8.14): "Can someone with no database or server background open the app, understand what each number means, and say what the evidence does and does not show?"

**Rule definitions:**

Permitted wordings, verbatim from §6.6. Components and the plain-summary builder call the functions in `web/src/lib/copy/wordings.ts`.

| Situation | The only permitted wording |
|---|---|
| A source with a **recording threshold** shows no event (for example `system_health` captures lock waits above 30 s and latch waits above 15 s, per Microsoft's page, S-16) | "Not observed in <source>. This source only records <threshold>; shorter waits would not appear." Never "SQL was not waiting" |
| A source with a gap, sampling or retention limit shows no event | "Not observed (gap or sampling: <detail>)." Never "ruled out" |
| A qualifying event overlaps a stalled audit interval, join class unique | "A <source> session had a <event> of <n> s overlapping this interval (Correlation)." Never "the API waited for SQL" |
| A qualifying event overlaps, join class ambiguous | "Possible overlap (ambiguous: <k> candidates)." Listed, not counted |
| An audit duration is large | "Audit create took <n> s as measured from the client side." It includes driver, connection pool, network and server time; it is never "the database was waiting" without a linked source |

Copy lint (acceptance for every slice; fails the build):
- A causal verb ("caused", "because", "waiting on", "blocked by", "due to") next to a label weaker than the stated standard.
- Any wording in the table above that is paraphrased.
- Reading level above about 8th grade, or long sentences, or passive voice (§8.14 writing rules).
- A technical term with no hint and no glossary entry (undefined-term check against the glossary).
- Certainty beyond the evidence label. The only strength words are Symptom, Correlation and Strong correlation (`web/src/lib/copy/types.ts`). "proven" never appears.
- A measurement with a cause named for it. Numbers without a unit and window. Blame language about people or systems.
- Fixtures: a positive set that passes; a negative set (each causal verb with each weak label) that must fail.

**Falsification:** Five non-engineers (support, account or business staff) read the hints and glossary on demo data, then answer five fixed questions (for example "Does this screen show that the database caused the slowness?"; correct answer: no). Fewer than four of five get four of five right: rewrite the words, retest, and do not call the slice done. This tests comprehension of the words; no cause is dropped by it.

**Evidence inputs:** None. P14a reads no source. Demo data is used for examples and tests only.

**Overhead:** None (local UI).

**Privileged operations:** None.

**Retention:** Only a per-viewer browser flag, the "tour seen" flag named in §8.14. The app works without it. Nothing is stored from real data. (Flag is used by P14b; see open point 3.)

**Provenance:** No new output cells. A plain summary restates an existing finding and keeps that finding's source row/file and hash. Inference: §8.14 does not state this.

**Plain-language copy:** All on-screen words, hint text and glossary entries live in one reviewable file, `web/src/lib/copy/deck.ts` (not yet created; `types.ts` defines `Deck` and `Term`). Rules from §8.14: reading level about 8th grade; short sentences; active voice; a hint the first time each technical word appears on a screen; everyday words ("waiting" over "blocked", "saved" over "persisted"); a glossary entry of two sentences plus a "what it does not mean" line. Reviewed by a non-engineer before the slice is called done.

**Positive demo:** A first-time user correctly explains a "not observed" result (§8.14). §8.14 runs this after the tour; P14a has no tour, so the P14a run uses hints and glossary only (open point 3).

**Negative demo:** A hypothesis blocked by a guard shows the plain-language reason, not an error code (§8.14). Fixture: a guard-blocked hypothesis; the shown text is plain words.

**Approvals needed:** None (no access, no data). Gate to call it done: non-engineer content review (§8.14). Decision R8 is still open; this gate is not granted.

**Stop condition:** §5.4 rule 3: retired if never used in a ledger entry after three closed incidents. Rule 2 exempts P14 as a usability slice.

**Open points (spec ambiguities, not resolved here):**
1. `web/src/lib/copy/deck.ts` does not exist. Commit 2f93be5 has only `types.ts` and `wordings.ts`.
2. The copy lint says "weaker than the stated standard" but no spec text says which evidence label is the standard.
3. §8.14's positive demo and retention flag belong to the tour (P14b). A hints-and-glossary version of the demo is needed for P14a.
4. §5.4 rule 3 asks whether a slice was "used in a ledger entry". The spec does not say whether hints or glossary entries count as use.
5. The non-engineer content review (R8) is open. P14a cannot be called done until it is granted.
