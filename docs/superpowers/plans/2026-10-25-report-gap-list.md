## Roadmap coverage summary

- In a plan but unbuilt: B9 step-change dating (addendum, deferred), P1c per-filter timings (blocked), theory engine (held), thin timeline P8 (needs two validated sources).
- Built (P2-lite): B1, B2, B3a, B6, B6g, B12, B12r, A3.
- In no plan: heat map, two-day overlay, hour-of-day aggregate, daily trend table with busy-day logic, size buckets, job-health trend, time-zone picker beyond UTC/Local, ranked logs-to-collect list, chart click-to-zoom.

## Top 8 to add, in order

1. **Day x hour heat map with zoom (rows 2, 22).** Cells are day x hour with p95 or slow-rate shading, cells under 5 requests dashed as noise, and a click sets the analysis window to that hour and opens its slowest requests.
2. **Daily trend table (row 1).** One row per day (lift the 7-day cap for a daily-rollup mode, up to 120 buckets) with sync count, background count and host CPU, an arrow versus the previous day with at least 100 requests, low-traffic days greyed and excluded from comparison, a partial last day flagged, and a CSV button on every table.
3. **Two-day hourly overlay (row 3).** Pick any two days and draw p95, request count and host CPU on one hour axis, one line per day, with the zone named in the caption.
4. **Step-change dating plus endpoint daily p95 (row 4).** Implement B9: two-segment fit on daily p95 for the top 10 operations (>= 5 days per segment, ratio >= 2, traffic ratio within 0.67-1.5, >= 3 operations sharing the break date +/- 1 day), then feed the date into the existing movers list and add a click-through to one endpoint's daily p95.
5. **Audit-insert series and fixed-duration stall detector (row 10).** Chart audit-create delay per day, flag repeated near-identical durations (for example a cluster within a 5 s band) and show insert time as a share of total request time.
6. **Hour-of-day slow aggregate and size buckets (rows 6, 14).** Add `hourOfDay` and `requestSizeBucket` breakdown dimensions to `breakdown.go` so slow-count and p95 can be read by hour and by payload size.
7. **Shared-axis host chart with restart markers (rows 16, 17).** Draw imported host CPU and SQL counters on the latency chart's time axis, with mongod restart and warm-up markers as vertical lines, reading from the existing case import tables.
8. **Per-filter timings (row 8) and a structured theory view (rows 18, 19).** Build P1c once T0.6b / T0.7 unblock it, and in parallel give each ledger entry a "settling observation" field with a matrix view plus a ranked "logs still to collect" list derived from the open entries.
