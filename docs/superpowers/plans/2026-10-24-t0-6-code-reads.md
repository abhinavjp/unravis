- Clock: app server clock (`DateTime.UtcNow`) for RequestInitiatedAt, CreatedOn, RequestCompletedAt, UpdatedOn. Mongo server sets none of them. All UTC; read-back ticks use `DateTimeKind.Utc` (RRL:116-126). No BSON date attribute on the model (`BrainPayroll.Service/Models/ApiAuditLog/ApiAuditLogServiceModel.cs:57-92`).
- ApiTime = `RequestCompletedAt - CreatedOn` in ms (QRH:102), where CreatedOn is the final, post-insert value. So it excludes the audit insert but includes everything after line 78, i.e. the action plus later filters up to OnActionExecuted.
- AuditCreateTime in the FINAL stored doc = post-insert header timestamp minus RequestInitiatedAt (QRH:101 after the update). It spans the whole start phase (config lookup, user lookup, async-job lookup, client IP, DI resolve, Mongo client creation, the insert), not just the insert. The schema doc says "cost of inserting" (`docs/api-audit-log-schema.md:36`); the code says it is broader.
- Failure shape: if the end-stage update never lands, the doc keeps the insert-time values (CreatedOn pre-insert, ApiTime null, RequestCompletedAt null).
- Hangfire path differs: it stores the pre-insert `apiAuditLog.CreatedOn.Ticks` (Hangfire handler:76), so there CreatedOn stays pre-insert and AuditCreateTime excludes the insert.
- Registration: `config.Filters.Add(new RequestAndResponseLogHandler())` is active in `BrainPayroll.Api/App_Start/WebApiConfig.cs:47`; commented out in the `.Core`, HangfireServer variants (same file, line 47).

## 2. AccountId

- On `master` there is NO `AccountId` field in `ApiAuditLogServiceModel` (fields at ApiAuditLogServiceModel.cs:17-116). No code assigns it.
- Only trace: Hangfire jobs embed it as text, `hangfire:// AccountId: <id or Unknown>`, from the job token (`HangfireRequestAndResponseLogHandler.cs:55, 62, 123, 132`); "Unknown" when token or AccountId is null.
- Not merged yet: commit `07c01384f3c` (Parth Patel, 2026-10-13, "BR-23116") adds `public int? AccountId` and sets it in both stages. It exists only on `origin/BR-23415-jeel` among known refs (this clone may be stale).
  - Web API: `AccountId = GetAccountId()` at start and end; reads `ITokenData.User.AccountId`; null when the token has none or the value is <= 0.
  - Hangfire: `token.AccountId` when `> 0`, else null.
- So AccountId is null on any document written by `master` code, and null on the new code for unauthenticated requests (no token user), tokens with no account, and token AccountId <= 0. `UserId` is likewise null when `ITokenData.User` is null (RRL:419-427).

## 4. Retry, swallow, timeout

- No retry wrapper or Polly policy on the audit path. The only Polly use is `PollyRetryExecutor` for Housekeeping (`BrainPayroll.Service/Infrastructure/HousekeepingServiceConfigurator.cs:43`), unrelated.
- Exceptions are swallowed and logged: the whole RRL start and end bodies run inside `ServiceResponseExceptionHandler.Handle`, which catches `Exception`, calls `LoggerService.ErrorLog` and returns a failure response (`BrainPayroll.Service/Helpers/ServiceResponseExceptionHandler.cs:11-31`). `SVC.CreateApiAuditLogs` is wrapped the same way (SVC:50-57). `ThreadHelper.Start` also catches and logs (`Helpers/ThreadHelper.cs:37-47`).
- A failed insert means no `AuditLogId` header, so the end stage returns early (RRL:111-114) and the request still proceeds. Failed or lost updates (e.g. bag unflushed at process recycle) leave the insert-time doc; the end-stage per-item errors in `UpdateItemsAsync` are collected but the caller does not await or inspect them (MC:305-318).
- No explicit timeout or cancellation token anywhere on the insert.

## 5. What the code supports about the ~28 s AuditCreateTime

- A stored AuditCreateTime of ~28 s means (post-insert `UtcNow`) minus (first line of the filter) was ~28 s, both read from one app-server clock in one request. Clock skew between Mongo and app is not involved.
- That interval contains only: config lookup (`ApiAuditLogsCommonService`, cache plus JSON file on a miss), `GetUserId` (DI), async-job lookup, client IP, DI resolution of the audit service (which constructs Mongo clients), and the blocking `InsertMany` (RRL:47-78, SVC:54-55).
