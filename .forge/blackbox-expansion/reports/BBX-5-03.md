### Note: the `housekeepFn` seam (only structural addition)

`Store.Housekeep` in this codebase ALWAYS returns `nil` error (blocked removals go to `Skipped`; disk-read errors break the free-space rule). The recorder's `err != nil` housekeeping branch is therefore unreachable through the real store, and the mandated `TestHousekeepingFailureFixedCode` cannot be written without a seam. Since only recorder.go/recorder_test.go are in scope, the seam lives in recorder.go: `var housekeepFn = (*Store).Housekeep` (method expression, default behavior identical, one call-site change). Tests swap it with `t.Cleanup` restore; no `t.Parallel` exists in the package, so the swap is race-free. No new goroutine/ticker.

### Violation

`rollbackLocked` (store.go:422) wrote `Event(EventWriteFailed, "could not cut a half-written line out of "+name+": "+err.Error())`. The by-name `os.Truncate` returns a `*PathError`, so the event detail carried the recording file name, the FULL recordings folder path, and the OS error text into `manifest.json` — which is copied into snapshots and leaves the box. HIGH C10 (fixed codes only) + no-text violation. The branch fires only when both the handle truncate and the by-name truncate fail; the existing `codeFailWriter` embeds a working `*os.File`, so its rollback always succeeded at the handle step and never reached this line — untested until now.

### Test design (exercises the fallback branch)

`cutFailWriter` wraps the real `*os.File`: while `fail` is set, `Write` and `Truncate` return the injected `secretEventText` error, and `Close` also removes the file — so after `rollbackLocked` closes the handle, the by-name `os.Truncate` fails too (file gone) and the event branch actually runs. Cross-platform, no OS-specific tricks. The test:

1. Appends one good sample, then fails the second write → asserts exactly ONE `EventWriteFailed` event whose detail is exactly `write-failed` (via the existing `fixedEvents` helper), and that the detail contains no substring of the temp folder path, the injected error text fragments (`secret driver text`, `C:\instances`, `MSSQL$PROD1`), or the file name.
2. Recovers (`fail = false`), appends again, closes the run — the store keeps going after the failed cut.
3. Reads the SERIALIZED `manifest.json` from disk (what ships in snapshots) and asserts it contains neither the folder path (raw and JSON-escaped backslash form) nor any injected-text fragment.

Red confirmed before the fix: the test failed with detail `"could not cut a half-written line out of bb-20261027-10.ndjson: open C:\Users\...\Temp\TestStoreRollbackCutFailureEventIsFixedCode...\001\bb-20261027-10.ndjson: The system cannot find the file specified."` — proving the branch is reached and the leak was real. Green after the one-line fix.
