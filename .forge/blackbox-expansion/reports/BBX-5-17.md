## Decisions worth a reviewer's eye

1. **Precedence in `pickKey`**: the `blackbox` branch sits first (right after `pretend`), ahead of `denied`/`off`, and needs `laneHasShape`. Rationale: BBX-5-16 gives the lane to Blackbox ahead of held-sql/qs-file/api-seen, so when the server names `blackbox` the lane *is* Blackbox data — a Query Store `off`/`denied` row must not stamp "Not recorded" over drawn blocks. If the owner wants the words to follow Query Store instead, it is a one-line move and one test flip. It still requires a drawn shape, so it can never dress an empty lane as a source.
2. **`since` needed one parser line** (`web/src/lib/tracing/model.ts`) — outside the packet's file list but inside `web/`, and it is what makes Do item 3 possible on the real path (CLAUDE.md: finish the real data path, not the demo). The field stays absent when the server sends none, exactly like `readThrough`, so every existing lane test compares unchanged.
3. **`dbShortBlackbox` = "sampled every 15 seconds"** rather than reusing `laneBlocks(minutes)` ("saved in 15-minute blocks"), which would have been wrong for 15-second samples; the shape stays `blocks`.
4. **The 15 s is fixed in the copy**, per the packet's mandated sentence (and the server's own fixed label). If a recording is configured with a different interval, the label still says 15 s while the blocks follow the real interval — flag for the live check; a `dbSrcBlackbox(rate, date)` would need the server to send its interval (it does keep `intervalSeconds` in the manifest, but not on the lane today).
