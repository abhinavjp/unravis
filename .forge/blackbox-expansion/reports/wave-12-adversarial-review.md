## Detailed Findings

**W12-01 — Complete zeros do not prove SQL coverage**

**The Flaw:** [tracing_blackbox.go:129–149, 173–219](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing_blackbox.go#L129), `bbLaneSamples`/`blackboxSQLLane`, discard samples without a valid batch counter and use the host manifest's first/last timestamps as coverage. [tracing.go:1042–1054](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing.go#L1042), `tracingBuckets`, fills every other cell with `Count:0, Complete:true`. No SQL-specific continuity or manifest-gap check follows. [reader.go:513–535, 589–599](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/reader.go#L513), `ReadReport.Incomplete`/`ReadSamples`/`readFile`, ignore `Newer` and `Torn` for completeness, silently cut to the newest 192 files, and silently skip malformed interior lines. The lane also skips over-cap counts without downgrading coverage (tracing_blackbox.go:179–190).

**Exploit / Failure Scenario:**
1. Preconditions: a case has a readable recording with valid SQL samples before and after an incident. During the incident, PDH fails, SQL stops, or the optional group is skipped; host samples/files remain readable. [groups.go:164–174](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/groups.go#L164), `groupCollector.Collect`, explicitly permits this.
2. Missing SQL samples disappear from `kept`; `rep.Incomplete()` is false. Interior buckets remain complete zero, suggesting no database activity precisely where evidence is absent. A long recorder gap has the same result.
3. A valid tracing request over more than eight days can also lose earlier files to `MaxReadFiles` while their buckets remain complete inside the manifest envelope. An over-cap numeric input can produce an entirely zero, complete lane; [tracing_blackbox_test.go:438–450](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing_blackbox_test.go#L438) currently expects those zero totals.

**Remediation:** Track accepted SQL observation intervals and per-instance coverage, not just host bounds. Carry skipped/corrupt/newer/capped reasons through `ReadReport`; flag affected buckets unknown/partial and surface a fixed warning. Preserve numeric overflow bounds, but do not equate rejected numbers with observed zero. Test internal gaps, optional skips, partial instance loss, invalid interior lines, newer versions, numeric rejection and 193 overlapping hourly entries.

**W12-02 — Batch-rate counts have the wrong interval and bucket support**

**The Flaw:** `bbLaneSamples` takes only `Manifest.IntervalSeconds` (tracing_blackbox.go:137–139); `blackboxSQLLane` rounds `rate * interval` and assigns it wholly to the bucket containing `s.T` (175–192). [manifest.go:81–87](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/manifest.go#L81) distinguishes configured and effective intervals. [recorder.go:163–167, 200–205](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/recorder.go#L163), `Recorder.Run`/`Tick`, actually changes cadence. [sqlhost.go:28–32, 141–155](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/sqlhost.go#L28) feeds a PDH rate, not a count or duration; [engine.go:107–112](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/engine.go#L107), `processRate`, passes that rate through.

**Exploit / Failure Scenario:**
1. Preconditions: base cadence 15 seconds; budget recovery re-enables optional SQL counters while effective cadence is 30 seconds. This is allowed by [budget.go:81–94, 120–132](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/budget.go#L81), `Cycle`/`stepBack`.
2. A 100-batch/s reading over a 30-second measurement span is counted as 1,500 rather than 3,000. A single latest effective-interval field cannot reconstruct all historical cadence changes either.
3. Independently, activity measured over 10:00:45–10:01:00 is assigned to 10:01, not the preceding interval. For a window ending at 10:01, `ReadSamples` excludes the 10:01 observation entirely. Boundary samples can also contribute a whole nominal interval to a much shorter clipped bucket.

**Remediation:** Preserve each rate's observation start/end or measured elapsed interval; read the necessary boundary observations and apportion overlapping intervals into clipped buckets. Keep unknown spans unknown across resets/restarts. Explicitly label integrated batch counts as estimates, not query durations/concurrency. Validate known-rate totals and minute edges under 5/15/30/60-second cadence, changes, jitter and restarts. No new int64-wrap defect was found: the present `1e15` count guard is below both int64 and JavaScript exact-integer limits; its silent-rejection semantics are W12-01.

**W12-03 — Blackbox ignores the selected source set and erases richer evidence**

**The Flaw:** `caseTracing` builds selected SQL/IIS lanes, then invokes Blackbox without passing `sel` (tracing.go:1116–1135). `bbLaneEntry` scans all case tags and takes the first name match (tracing_blackbox.go:72–104). Once one reading qualifies, the builder replaces sources/buckets and explicitly empties events/import coverage (202–225). Held Query Store is bypassed; [tracing_qsfile.go:101–104](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing_qsfile.go#L101) and [tracing_apiseen.go:92–95](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing_apiseen.go#L92) also refuse a Blackbox lane. Existing [tracing_sqllive.go:32–52](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing_sqllive.go#L32), `layerSQLLane`, demonstrates preserving distinct event evidence without summing it into aggregates.

**Exploit / Failure Scenario:**
1. Preconditions: the case has a Blackbox tag and an imported Query Store/XE source. The investigator explicitly selects only the import using `sourceIds`.
2. The valid selected import is read, but one SQLHost observation in the case's unselected Blackbox wins. Its machine-wide batch totals replace the selected database's evidence; events and their provenance disappear. A partially readable Blackbox wins too.
3. In wave 13, positive batch counts cannot draw the expected concurrency shape (W13-01), so adding a recorder can make a previously usable SQL lane appear not recorded.

**Remediation:** Honor explicit source selection. Treat batch throughput, Query Store duration and XE markers as different measures; preserve separately attributed markers and use a documented, coverage-aware selection rule rather than unconditional replacement. If priority is a product decision, expose that choice instead of silently overriding a selected source. Regression-test selected-import-only, full Query Store plus partial Blackbox, and XE-plus-Blackbox cases. This is not an authorization bypass: all sources are in the same authorized case.

**W12-04 — Bounded file count is not a bounded read**

**The Flaw:** `ReadSamples` accumulates every accepted sample before sorting/deduplication (reader.go:522–559); `readFile` has neither a total-byte nor sample-count budget (576–611). The 4 MiB bound is per line only (614–628), and `FileEntry.Bytes`/`Samples` do not enforce limits. Folder cancellation abandons blocking OS operations in helper goroutines (200–215, 221–245, 256–276). [blackbox.go:109–116, 1236–1263, 1297–1316](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/blackbox.go#L109) supplies deadlines and window limits, not read admission limits. The tracing path likewise adds no read semaphore.

**Exploit / Failure Scenario:**
1. Preconditions: an authenticated local user selects an untrusted/corrupt recordings folder or endpoint, or an already saved share stops answering. No unauthenticated remote reachability is assumed.
2. One validly named hourly file contains many individually legal lines and in-window timestamps. Every decoded sample, including unrelated groups, occupies memory before the SQL lane filters it. The 192-file cap and small final response do not cap that allocation.
3. Repeated permitted reads of a dead share can return on deadline while leaving more OS helpers outstanding. Existing [reader_test.go:517–554](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/reader_test.go#L517) proves caller cancellation only, releasing its fake blocker afterward; it does not prove bounded outstanding operations. No exhaustion attack was executed.

**Remediation:** Enforce cumulative input bytes and sample/decoded-object counts, check cancellation in the decode loop, and preferably aggregate the needed fields incrementally. Add bounded per-source/global read admission, including outstanding uncancellable OS calls. Mark limits as incomplete, not clean EOF. Related endpoint boundary: [server.go:259–268](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/server.go#L259), `readSQLStatus`, uses unbounded `os.ReadFile`; cap it before allocation too. Its separate precondition is a corrupt/oversized status file writable by an authorized SQL-folder principal, not an ordinary HTTP caller.

**W12-05 — Lexical path validation does not enforce filesystem containment**

**The Flaw:** `FolderSource.OpenFile` accepts a valid recording basename, then `DirAccess.Open` uses ordinary `os.Open` (reader.go:125–128, 180–189). `Server.handleFile` similarly opens and sends the raw target without a no-follow/containment check (blackbox/server.go:310–329). [manifest.go:104–126](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/manifest.go#L104) blocks `..`, separators and alternate filename syntax, but a valid `bb-YYYYMMDD-HH.ndjson` entry can itself be a link. The manifest need not list a file for `handleFile` to serve it.

**Exploit / Failure Scenario:**
1. Preconditions: someone can create/replace a recording entry or an ancestor with a filesystem link; the reader/service account can read its target. On HTTP, the requester also possesses the read key. The installed default ACL grants ordinary users read/list, not write ([service_windows.go:24–29](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/service_windows.go#L24)); this is not a demonstrated default-install privilege escalation.
2. A permitted basename resolves outside the intended recordings folder. The folder path opens that target; the HTTP handler can return its bytes regardless of whether they are NDJSON. A bad imported folder can therefore escape the lexical boundary without `../`.
3. **Unverified Assumption:** exact deployed NTFS link/junction permissions and reparse behavior have not been exercised. No link was created and no private target was read.

**Remediation:** Use a handle-based, race-resistant containment/no-follow policy for both manifest and hourly-file opens, validating ancestors and final objects; refuse non-regular objects and Windows reparse aliases unless an explicit trusted-root policy permits them. Test symlink/junction/ancestor substitution without reading real private data. Do not weaken SQL ACLs to make a reader work.

**W12-06 — Dump traversal caps callbacks, not enumeration cost**

**The Flaw:** [dumps.go:45–82](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/dumps.go#L45), `catalogueDumps`, uses `filepath.WalkDir`, which reads a directory's entries for lexical traversal before visiting its children. The callback's 500-entry cap therefore does not bound the root directory listing/allocation. Later roots are still attempted after the shared cap is exhausted. `groupCollector.runGroup` measures only after `Collect` returns (groups.go:182–196), so its one-second budget cannot interrupt that first listing. The five-minute cache bounds frequency, not one scan's cost.

**Exploit / Failure Scenario:**
1. Preconditions: an ordinary incident accumulation or a principal with write access leaves a very large WER/CrashDumps directory under a fixed root. No arbitrary root injection is needed.
2. The service enumerates the whole directory before stopping at callback 501. While that filesystem call runs, the serial host tick waits; high allocation/latency can violate the recorder footprint.
3. A late-sorting recent dump can be omitted because 500 earlier names exhausted the visit budget. The output contains the newest 200 of the visited subset, not necessarily the newest 200 under all roots. [dumps_test.go:79–105](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/blackbox/dumps_test.go#L79), `TestDumpsCaps`, checks returned entries, not how many directory entries were allocated/read.

**Remediation:** Replace whole-directory traversal with bounded batched directory reads, stop before opening further roots after budget exhaustion, and retain a bounded newest-entry heap. Expose truncation/unreadable status rather than implying a complete newest-first catalogue. Measure a large-directory scan's CPU/RSS/wall time and host-tick delay. **Unverified Assumption:** junction safety is not established by `ModeSymlink` alone in this review; Go 1.27.3/runtime-specific NTFS tests must cover root and nested junctions. The source contains no dump-content open: only `DirEntry.Info`, basename, size, mtime and parsed target (dumps.go:68–80). No dump-content disclosure is asserted.
