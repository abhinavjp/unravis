**Exploit / Failure Scenario:**

**W13-02 — Query Store fallback rewrites Blackbox unknowns into zeros**

**The Flaw:** `SlowCallScreen.qsBlockSeconds` uses the newest saved SQL day's Query Store interval for every SQL lane; `toLaneIn` applies it whenever `lane.blockSeconds` is absent (SlowCallScreen.svelte:104–129). Blackbox sets `BlockSeconds=0`, which the server omits ([tracing.go:468–470](file:///C:/Users/nachi/Documents/Qoder/2026-11-13/e31b14d4/unravis/internal/server/tracing.go#L468)); the parser accepts only positive block lengths (model.ts:285). Therefore a Blackbox lane inherits unrelated Query Store grouping. `regroupBlocks` (callLanes.ts:110–134) includes null-cell time in its denominator and writes a group's average back into every cell, including null/incomplete ones.

**Exploit / Failure Scenario:**
1. Preconditions: the case has a saved Query Store day with a 15-minute interval and also a Blackbox lane. In one block, a complete count-zero minute is followed by positive-count/no-duration minutes; the final minute is explicitly incomplete.
2. Before regrouping, the zero minute is `atOnce=0`, the positive/no-duration and incomplete minutes are null. `toLaneIn` supplies `blockSeconds=900` from Query Store even though the selected source is Blackbox.
3. `regroupBlocks` sets `any=true` on the zero, divides zero busy time by the entire block, and replaces all fifteen cells with zero. A bounded in-memory check reproduced **15/15 zero cells**, including the `complete:false` final bucket. This destroys both semantic unknowns and the server's explicit gap flag.
4. `gapRuns` checks only the resulting `atOnce === null` (CallLanes.svelte:88–103); it can no longer hatch those gaps. The minimap receives the same transformed cells (SlowCallScreen.svelte:224–227).

**Remediation:** Apply Query Store block semantics only to matching Query Store provenance and its own source interval. Never borrow a saved day's block length for Blackbox or API-seen data. Keep coverage independent of display averaging; unknown/incomplete cells must remain unknown. If interval totals are distributed, distribute only across a proven source interval, never across unavailable time. Add mixed known/null/incomplete tests, not only all-null and fully-covered block tests; verify source changes and missing/zero block lengths.

**Remediation:** Send source-specific metadata: host PDH batch throughput versus SQL-service DMV sampling, observation cadence/range, coverage and what `since` means. Derive captions from those fields, or use neutral “sampled host batch activity” wording without an unsupported cadence. Keep server and client source descriptions consistent. Validate five-second, changed-cadence, omitted-group and multi-instance recordings. Make throughput-versus-concurrency explicit in labels, legends and readouts (drillCopy.ts:93–104, 130), not merely in a tooltip.

**W13-04 — An absent date is replaced with a real-looking sample date**

**The Flaw:** `dbState` unconditionally substitutes `SAMPLE_DATE = '11 Nov 2026'` when `laneSince` is absent (dbState.ts:48, 87–94, 113–114); the fallback is not guarded by demo mode. `parseLane` drops unparseable `since` (model.ts:287–288), and the input/parsed types explicitly allow absence. The test at drill.blackboxlane.test.cjs:73–77 locks in the fabricated date.

**Exploit / Failure Scenario:**
1. Preconditions: a Blackbox-tagged lane can draw at least one cell, but an optional `since` is absent or rejected by the parser. An in-memory check with `laneSince:null` reproduced the fallback without a pretend/demo state.
2. The UI supplies a concrete historical date instead of saying start time unknown. This can be mistaken for evidence of recording availability.
3. **Unverified Assumption / reachability limit:** the normal current `blackboxSQLLane` always assigns `Since` (tracing_blackbox.go:194, 224). No live current-writer response lacking it was observed. This is a confirmed defensive/optional-contract bug, not a claim that every real response contains a false date.

**Remediation:** Render “recording start unknown” or omit the date unless a validated source timestamp exists. Keep demonstration dates exclusively behind an explicit demo path. Test missing, invalid and valid dates after `parseTracing`, without forcing `laneHasShape` independently of real buckets.
