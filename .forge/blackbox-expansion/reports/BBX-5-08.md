## Implementation summary
- `type State struct { Interval time.Duration; Failures int; AutoOff bool; SlowStrikes int; State string }` with JSON tags `interval/failures/autoOff/slowStrikes/state` — fixed fields only.
- Fixed states: `on`, `backing-off`, `auto-off`, `denied` (constants `StateOn/StateBackingOff/StateAutoOff/StateDenied`). No error text, instance names, or driver messages are ever stored.
- Constants: `BaseInterval=15s`, `MaxInterval=15min`, `DemotedInterval=60s`, `AutoOffFailures=10`, `SlowStrikeLimit=3`.
- `NewState()` — on at 15 s (used by Load for first start and by OwnerEnable).
- `OnSuccess()` — no-op when AutoOff (success can NEVER clear auto-off); otherwise resets Failures/SlowStrikes, halves Interval toward base (floor 15 s), State=on.
- `OnFailure(permission, ceiling bool)` — Failures++; Interval doubles from >=15 s base, capped at 15 min; State=backing-off; if Failures>=10 OR permission OR ceiling → AutoOff=true, State=auto-off (denied for permission/ceiling).
- `OnSlow(used, limit)` — used > limit/2 → SlowStrikes++ else reset; >=3 strikes → Interval raised to 60 s only if currently below 60 s (15 s items demote; a longer back-off interval is never lowered). Exactly 50% is not a strike.
- `OwnerEnable(s *State)` — the ONLY path that clears AutoOff (full reset to NewState). Verified: the only writes of AutoOff are `true` in OnFailure and in Load's fail-closed path; the only clear is OwnerEnable.
- `StatePath(folder)` = `<folder>\sql\state.json` (filepath.Join).
- Persistence seam (injectable, tests use an in-memory map, no real disk):
  - `readFile = os.ReadFile`
  - `writeFile = func(path, data)` → `os.MkdirAll(dir, 0o700)` + `os.WriteFile(path, data, 0o600)` (one small file write).
- `Save(path, State) error` — json.Marshal of the fixed struct, then writeFile.
- `Load(path) (State, error)`:
  - missing file → NewState() (first start), nil error;
  - persisted AutoOff STAYS auto-off (restart cannot clear); normalize() forces State to auto-off/denied whenever AutoOff=true, even if the file was tampered to say `"state":"on"`;
  - unreadable or corrupt JSON → fail CLOSED: returns `{AutoOff:true, State:auto-off}` plus the error, so a damaged state file can never silently re-enable the service;
  - normalize() clamps Interval to [15 s, 15 min], floors negative counters, and keeps State within the fixed four (unknown labels derive on/backing-off from interval when not auto-off).
- No goroutine, ticker, timer, or sleep anywhere in the file (grep verified). Runner wiring (load at start, save after every change) is BBX-5-10's scope; signatures match its packet (`State/Load/Save`).

## Design decisions / interpretations
- `OnSuccess` under AutoOff changes nothing (strictest reading of "auto-off does not recover on success").
- Fail-closed Load on unreadable/corrupt state (returns auto-off + error) — chosen so a damaged/torn state file cannot silently re-enable SQL sampling; missing file still means first start (on).
- Slow demotion raises any sub-60 s interval to 60 s (covers 15 s items per C7; never lowers a longer back-off interval).
- Save creates `<folder>\sql` with 0o700 and writes state.json with 0o600; the folder's DACL protection is the service installer's scope (BBX-5-01), not this packet.
