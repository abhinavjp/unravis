## Design / wire contract (for BBX-5-17)

Selection order in `caseTracing`: **blackbox > held-sql/layered-sql > qs-file > api-seen > not-recorded**. The blackbox attempt runs only for the SQL lane when it is not disabled and its clock is not unchecked; on any miss (no blackbox tag, name not in the saved list, unreadable place, no samples, no `SQLHost.BatchRequestsPerSec` reading in the window) it returns the lane untouched and the existing chain runs exactly as before — never a zero lane, never error text.

When the case's first `blackbox` source tag (same rule as `applyBlackboxLane`) resolves to a saved entry whose window samples carry `SQLHost.BatchRequestsPerSec`:

- `reasonCode: "blackbox"` — the source key (same slot the web dbState reads as `laneReasonCode`).
- `sources: [{sourceId: "blackbox", label: "Blackbox sampling every 15 s since <2 Jan 2006 UTC date of first sample>"}]` — fixed sentence, e.g. `Blackbox sampling every 15 s since 20 Oct 2026`.
- `since: "<first sample RFC3339>"` — new optional lane field; the recording's `manifest.FirstSample` (falls back to the window's oldest kept sample when the manifest has none). It is the recording start, not the window start.
- Blocks: per sample, `round(sum(instance BatchRequestsPerSec) × intervalSeconds)` summed into its axis cell (`intervalSeconds` from the manifest, default 15). Instances with a missing/negative/NaN/Inf reading contribute nothing (missing never 0). `scanned` = total; `state: "events"`, `origin: "case"`, `consistency: "stored-as-of"`, `asOf` = newest kept sample, `complete: true`.
- No text: `events: []`, `reason: ""`, no instance names, no query text, no timing figures invented (`avgMs/p50Ms/p95Ms/maxMs/busyMs` stay absent — the sampling records rates, not durations). `blockSeconds: 0` (15 s samples are shorter than any bucket).
- Read path: `blackboxHub.source(entry)` (sealed key, same as the host lane) → `blackbox.ProbeSource` → `blackbox.ReadSamples` for `[axis.Start, axis.End)`, bounded by `bbReadTimeout` (40 s) and the reader's own 192-file cap. On demand per request; nothing kept between requests; no goroutine/ticker added (the reader's existing cancellation helpers are unchanged).
