## Notes / interpretations

1. Pool `running=true`: applicationHost.config lists CONFIGURED pools and carries no run-state; the repo has no existing entry point for app-pool running state (no appcmd/WAS/ServerManager code), and the packet forbids writing a new enumerator. A configured pool is therefore offered as a target with `running=true`, matching the packet's example JSON (`"appPools":[{"name":"...","running":true}]`). Services use real state (`running` filter). The live-check confirms pools on a real IIS server.
2. `detected` semantics (all-or-nothing): per the packet's explicit example ("no IIS config readable → detected=false, still return empty lists"), if EITHER source cannot be read the answer is `detected=false` with BOTH lists empty; the handler also forces empty lists whenever `detected=false`. Consequence: a Windows host without IIS returns `detected=false` even though services are readable. This is the literal packet reading (rule 3: undetected → empty lists + detected=false, never 0-as-fact).
3. Route-table coverage row: `TestRouteTableCoversEveryRoute` (routes_test.go) requires a `routeCases` row for every registered route. routes_test.go is outside the packet's file scope, so the new route's row is appended from an `init()` in blackbox_test.go (same package). This keeps the change within the two allowed files while the route remains fully exercised by all three route-table guards (coverage, per-method status, token-before-method).
4. Detection seam: implemented as `BlackboxDeps.DetectTargets` (nil → real `detectTargets()`), mirroring the file's existing `Scan`/`Open`/`Now` injection style rather than a mutable package global, so tests are parallel-safe. `detectTargets()` keeps the exact packet signature.
5. Dedup is exact-name (case-sensitive); sort is byte-wise ascending by name. configparse already validates pool names; SCM returns each service once.
