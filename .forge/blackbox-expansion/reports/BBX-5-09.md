  - `AG{DatabaseID uint32, SyncState uint8}` — no replica server names.
- **Decode path (C9)**: `decodeRows(rows []Row, dst interface{}, cap int) (truncated bool, err error)`. `Row = map[string]any` (alias; the Queryer row type — BBX-5-06's conn.go is not in this worktree yet, so Row is defined here). Each row's columns are mapped through the fixed `columnKeys` table (SQL snake_case → the struct's camelCase JSON key, e.g. `io_stall_read_ms`→`readStallMs`, `size_on_disk_bytes`→`sizeOnDiskBytes`); **any column not in the table is rejected outright**, then `json.Decoder.DisallowUnknownFields` is the second gate against the fixed struct. `[]byte` driver values are normalized to string. `dst` must be a pointer to a struct slice and is left untouched on error. All errors are fixed codes (`errUnknownColumn`, `errWaitType`, `errDecode`, `errDst`) — no column names, row values, or driver text can leak into logs.
- **PIN — empty wait type**: in the requests decode path only (`case *Requests`), `WaitType == ""` is mapped to the fixed sentinel `WaitTypeRunning = "RUNNING"` **before** validation. `waitTypeRe = regexp.MustCompile("^[A-Z0-9_]{1,60}$")` is unchanged and still rejects `""` (asserted in tests); waits rows with `""` are still rejected.
- **Row caps (C6)**: `CapRequests=256`, `CapWaits=20` (TOP 20 in SQL), `CapFileStats=256` (TOP 256 in SQL), `CapSchedulers=1`, `CapTempdb=1` (both summed in SQL), `CapSemaphores=16`, `CapAG=64` ("others small"; judgment calls, see open questions). The loop stops at index `cap` (the n+1-th row) without decoding it, keeps `cap` rows, sets `truncated=true`; exactly `cap` rows → not truncated. **Not** dbhealth's 5000 cap; tests assert every constant is in (0, 256].
- **No wrapper type**: the packet says "choose fixed per-kind structs; the runner writes one NDJSON line per kind" — the 7 structs are the deliverable; BBX-5-10's runner composes the NDJSON envelope.
- **No names/text anywhere**: only string field in any struct is `WaitType` (regex-validated); everything else is numeric. No database names (ids only), no query text/login/host/program/paths/replica names representable.

5. Waits decode intentionally lands cumulative values in DeltaMs/DeltaTasks (BBX-5-12's documented "decode current cumulative values" flow); the delta conversion is that packet's job, not this one's.
