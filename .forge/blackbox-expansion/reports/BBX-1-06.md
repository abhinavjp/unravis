## What was implemented
- Reuses the lazy-DLL declarations from `extras_windows.go` (`pdh`,
  `procPdhOpenQuery`, `procPdhAddEnglishCounter`, `procPdhCollectQueryData`,
  `procPdhGetFormattedCtrValue`, `procPdhCloseQuery`, `pdhFmtDouble`,
  `pdhFmtCounterValue{CStatus uint32; _ uint32; Double float64}`). They are
  unexported but in the SAME package, so they are directly reusable;
  re-declaring them locally would be a compile-time redeclaration. Only two
  procs are new: `PdhExpandWildCardPathW` and `PdhRemoveCounter`.
- `pdhCounter{path string; handle uintptr; wildcard bool}`; `PDHSource` holds
  ONE query handle, the counter slice (expanded paths), the original wildcard
  patterns (needed to re-expand), and a `closed` flag.
  `var _ CounterSource = (*PDHSource)(nil)` on both platforms.
- `NewPDHSource(paths)`: `pdh.Load()` → one `PdhOpenQueryW`; per path,
  `isWildcard` (contains `*`, which covers `(*)`) → `PdhExpandWildCardPathW`
  (size call accepting PDH_MORE_DATA 0x800007D2, then multi-string parse) →
  `PdhAddEnglishCounterW` each expanded path; direct paths added as-is. ONE
  priming `PdhCollectQueryData`. Any open/add/expand failure closes the query
  and returns `nil, err` (no handle leak).
- `Collect()`: ONE `PdhCollectQueryData`, then per handle
  `PdhGetFormattedCounterValue(PDH_FMT_DOUBLE)` → `readingFrom` →
  `CounterReading{Path, Value, Status: CStatus, OK: CStatus==0}`. A per-counter
  API failure yields `OK=false` with the API status in `Status` (never
  Value=0/OK=true) and does NOT abort the collect. Closed source → error.
- `RefreshInstances()`: removes ONLY wildcard handles via `PdhRemoveCounter`,
  keeps direct counters' handles untouched, re-expands the stored wildcard
  patterns, re-adds via `PdhAddEnglishCounterW`, primes once. Called by the
  resolver only when the process set changes — never per tick. `Collect`
  contains no expansion and no add calls.
- `Close()`: one `PdhCloseQuery`, idempotent, safe on a zero value (guards
  `closed` and `query != 0`).
- `Paths()`: copy of the current expanded paths for building engine specs.
- `pdh_other.go` (!windows): `NewPDHSource` → `nil, errors.New("PDH counters
  are Windows only")`; stub `PDHSource` with `Collect`/`RefreshInstances`/
  `Close` returning that error and `Paths` returning nil, so callers compile
  cross-platform.
- No goroutines, no tickers, no process attach/pause; all syscalls happen
  inside New/Collect/Refresh/Close called from the tick loop. English names
  only (`PdhAddEnglishCounterW`); no `PdhAddCounterW` anywhere. No text
  captured — counter paths are fixed identifiers.

- `TestNewPDHSourceBadPathReturnsError` took ~39s: PDH validates the bogus
  object name against the performance library before failing. It needs no
  real counters (asserts failure only) and passes; the latency is inherent
  to PDH name resolution, not a leak or retry loop.
- `RefreshInstances` propagates expansion/add errors to the caller; if a
  wildcard matches nothing after a process-set change it returns an error
  with the old wildcard handles already removed (direct counters intact).
  Resolver wiring (later packet) decides how to surface that.
- If the instance list grows between the two `PdhExpandWildCardPathW` calls
  (rare race), the second call returns PDH_MORE_DATA and the constructor/
  refresh returns an error rather than looping; acceptable per packet scope.
- Reused the unexported same-package pdh declarations instead of
  re-declaring (redeclaration would not compile); this matches the packet's
  "reuse those declarations" intent.
