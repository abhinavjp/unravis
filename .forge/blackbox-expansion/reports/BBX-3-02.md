## Implementation summary (counter-group pattern as BBX-2-01 / http.go)
- `init()` → `RegisterGroup("proc10", true, newProc10Group)` — optional=true.
- Factory `newProc10Group(d GroupDeps)`: uses `d.Source` when injected (tests); otherwise `NewPDHSource(proc10Paths)` and returns the error on failure so `BuildGroups` skips it (non-Windows stub returns `errPDHWindowsOnly`). No build tag — OS independence via the `CounterSource` interface + pdh_other.go stub. Uses `d.Targets()`.
- `src.Paths()` (type-asserted `interface{ Paths() []string }`) gives expanded paths; `parseProc10Path` extracts the instance (text between `(` and `)`, including the `#N` suffix) and matches the counter suffix. Per-(instance,counter) `CounterSpec`s use `Field = inst + "\x00" + counter` (NUL cannot occur in a PDH instance name) and a fresh `NewEngine(specs, d.Cores)`.
- Kinds per packet: `% Processor Time` = `KindPDHRate` (engine gates behind two baselines, never clamps — multi-core CPU% not capped at 100); `ID Process` / `Working Set` / `Private Bytes` = `KindGauge`.
- `Collect(now, dt)`: re-expand ONLY when `g.changed != nil && g.changed()` (`d.ProcessSetChanged`) via type-asserted `RefreshInstances()` on the same query handle, then rebuild specs/engine. Then `src.Collect()` → `engine.Process` → build instance→PID map from the `ID Process` gauge (skip `_Total`/`Idle`/PID≤0), invert to PID→instance deterministically (sorted instances; first wins on duplicate PID). For each selected target: skip unless `Runtime == 2` AND `Start != 0` (identity (PID, creation time) confirmed); match instance by PID; fold emitted fields into `Proc10Target{Target: Key, CPUPct, WorkingSet, PrivateBytes}`. Working Set / Private Bytes converted float64→uint64 (guarded `v >= 0`). A target with no instance, or no valid field, is omitted; missing fields stay nil, never 0. Targets sorted by Key; `nil, nil` when none.
- `Close()` closes the source only when the factory created it (`owned` flag); `groupCollector.Close` picks it up via `io.Closer`.
- No goroutine, no ticker, no EventPipe/diagnostic pipe, no attach/dump, no text — PDH counter reads only (target keys + numbers). One PDH query handle per source, reused for the source lifetime.

## "confirm Start" interpretation
PDH Process counters expose no creation time, so "match by PID (confirm Start)" is implemented as: require `target.Start != 0` (the (PID, creation time) identity is confirmed) before matching by PID. This mirrors the resolver (`resolve_map.go` treats `Start == 0` as "not running" and never caches it). A selected runtime-2 target with `Start == 0` is omitted (covered in TestProc10PIDMap via `pool:stale`). Flag if a different reading was intended.
