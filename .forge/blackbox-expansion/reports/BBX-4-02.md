## Implementation summary
- `init()` → `RegisterGroup("tcp", true, newTCPGroup)` — optional=true (TestTCPGroupRegistered).
- Factory `newTCPGroup(d GroupDeps)`: uses `d.Source` when injected (tests); otherwise `NewPDHSource(tcpRatePaths())` and returns the error on failure so `BuildGroups` skips it (non-Windows stub returns `errPDHWindowsOnly`). No build tag on tcp.go — OS independence comes from `CounterSource` + the pdh_other.go stub + the tcptable twins.
- Specs: `\TCPv4|\TCPv6\Segments Retransmitted/sec` and `\TCPv4|\TCPv6\Connections Reset` = `KindPDHRate` (engine gates behind two valid baselines); each expanded `\Network Interface(<if>)\Output Queue Length` = `KindGauge` keyed by full path, summed in Collect via the aligned `queueKeys` list (no hot-path parsing).
- `Collect(now, dt)`: one-time `upgrade()` (see below) → re-expand ONLY when `d.ProcessSetChanged` reports a change (type-asserted `RefreshInstances()` on the same query handle, then rebuild specs/engine) → `src.Collect()` → `engine.Process` → sums. `tcpTableCounts()` supplies States. A failed PDH collect still allows States; a failed state query leaves States nil but keeps rates; both failed → `nil, nil` (collector records Missing). Missing fields stay nil, never 0.
- **Machine-wide sums need both families**: RetransmitsPerSec = v4+v6 only when both readings are valid; same for ResetsPerSec. A missing/invalid side leaves the field nil (a partial sum would implicitly zero-fill the missing family). OutboundQueue sums whichever interface readings are valid; none valid → nil.
- State counting: `tcpTableCounts()` (windows twin) loads lazy `iphlpapi.dll`, calls `GetTcpTable2` (size call + fetch), and hands the raw buffer to the platform-independent `tcpStateCountsFromTable(buf)` in tcp.go. That function reads ONLY the header `dwNumEntries` and each row's `dwState` DWORD at offset 0 (MIB_TCPROW2 stride 28). Address/port/PID bytes (offsets 4..27) are never read into any variable or struct. Counts per MIB_TCP_STATE 1..12, emitted sorted; scan capped at `maxTCPStateRows = 65536`; truncated buffers count complete rows only. The other twin returns an error. Injection point for tests: the `tcpGroup.counts` func field (set to `tcpTableCounts` by the factory, overridden per-instance in tests — no global mutation, no Windows needed).
- `Close()` closes the source only when the factory created it (`owned` flag); injected fakes are never closed (asserted in TestTCPRefreshOnChange).
- No goroutine, no ticker, no channels, no text — `grep -nE "go func|time\.NewTicker|time\.Tick\(|make\(chan|sync\." tcp*.go` → no matches. One PDH query handle per source, reused for the source lifetime; refresh re-expands on the same handle.

### Deviation from the strict factory pattern (deliberate, measured): deferred Network Interface expansion
The packet's group pattern puts every path in the factory's `NewPDHSource`. On this machine that broke the EXISTING host/clumsy tests: `RunHost` builds all groups BEFORE the status server listens, and the test rig allows only 5 s for listen (`clumsy_test.go:50`, `host_test.go:198`). Measured first-clumsy-test totals (cold PDH, quiet machine):
- baseline (no tcp group): 4.35 s
- tcp factory with all 5 paths: 6.21 s → "server never listened" failures in the full suite
- tcp factory with the 4 TCP counters only: 4.60 s

The `\Network Interface(*)\Output Queue Length` first expansion/add/prime costs ~1.6 s in-process; the TCP counters cost ~0.25 s. Fix (contained in tcp.go): the factory opens only `tcpRatePaths()`; the first `Collect` calls `upgrade()`, which once swaps in a full `tcpPaths()` source (closing the old query) and rebuilds the engine. By then the server is already listening, so the 5 s listen budget is untouched; the cost lands in the first sample, inside the rig's separate 5 s sample deadline. One attempt only — if the upgrade fails, the rate-only source is kept and OutboundQueue stays nil (never retried per tick). Injected sources are never swapped (`!g.owned` guard), so all fake tests exercise the full path set directly. Side effects, accepted: the fresh engine re-gates the rates for two baselines after the upgrade (same conservative semantics as a refresh), and the first real tick may exceed the 1 s per-group budget, marking optional tcp slow for one cycle (the budget's designed probe/skip/re-probe behavior). Full suite after the fix: PASS (81 s).

## Open questions / notes
1. **`\TCPv4|\TCPv6\Connections Reset` is cumulative, not per-second** (live-verified: 51981/200 and unchanged across 2 s). The packet mandates `KindPDHRate`, which was followed — so `resetsPerSec` currently emits the gated cumulative total, not a true rate. Recommend a follow-up packet switching these two specs to `KindRate` (engine delta with reset guard) once the owner confirms. Flagged, not silently changed.
2. Both-family rule: a machine without the TCPv6 object would fail `NewPDHSource` and skip the whole group (pre-existing PDHSource semantics, same as http/diskCpu). If IPv6-less servers must be supported, the source needs per-path tolerance — out of this packet's scope.
3. Deferred NI upgrade (above): one attempt; on failure OutboundQueue stays nil for the run. First tick may mark optional tcp slow for one cycle. Rates re-gate two baselines after the upgrade. All deliberate; flag if the owner wants different trade-offs.
4. "Sum over up interfaces": implemented as the sum over the interfaces PDH enumerates (no oper-status filter — PDH exposes none). Loopback/tunnel adapters with an Output Queue Length instance are included; confirm on a real server whether that matches intent.
5. GetTcpTable2 race: if the table outgrows the size call between the two API calls, the fetch errors and States is nil for that tick (retried next tick). No retry loop — bounded footprint.
6. Pre-existing test flake: the clumsy/host rigs' 5 s listen timeout fails randomly when several agents run the blackbox suite concurrently (proven on pristine baseline). Not caused by this packet after the upgrade fix; orchestrator may want to serialize full-suite runs across worktrees.
