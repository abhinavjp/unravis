## Unconfirmed / open questions
1. **"or a mandatory group is slow" widen clause.** The packet's `Cycle` text says widen when
   "already skipping optional (or a mandatory group is slow)". `GroupTiming(name, d)` carries no
   optional/mandatory flag, so the Budget cannot distinguish a mandatory slow group from an
   optional one. Implemented the literal primary wording: over-budget OR any slow group first sets
   `skipOptional=true`, then widens on subsequent such cycles (uniform for all slow groups). No
   named test exercises slow-group + `Cycle` widening, so this is untested by the packet. If the
   intent is that a slow group widens immediately on the first cycle, `GroupTiming` would need an
   optionality signal (out of scope for this packet's API). Flagging for BBX-1-07 integration.
2. **Base-5 step-back floor.** For base 5, step-back returns to base (5) once effective reaches the
   lowest rung (15), treating base as the floor ("never below base"). The packet's ladder prose
   (60→30→15) is written for the default base 15; base-5 step-back is not covered by a named test.
   Chosen behavior returns to the configured base after calm, symmetric with widen starting at base.
3. **Line budget.** Production `budget.go` is 133 lines (within the ~150 guideline). The required
   8 named tests plus the allocation check add 213 test lines; tests are mandated by the packet.
