## Implementation summary (established counter-group pattern, per http.go/diskcpu.go)
- `init()` → `RegisterGroup("iis", true, newIISGroup)` — optional=true; `Optional()` returns true.
- Factory `newIISGroup(d GroupDeps)`: uses `d.Source` when injected (tests); otherwise `NewPDHSource(iisPaths)` and returns the error on failure so `BuildGroups` skips it (non-Windows stub returns `errPDHWindowsOnly`; also skips when IIS is absent — wildcard expansion fails with `0xc0000bb8`). No build tag on iis.go — OS independence comes from the `CounterSource` interface + the pdh_other.go stub.
- After construction, `src.Paths()` (type-asserted `interface{ Paths() []string }`) gives the expanded paths; `parseIISPath` extracts the `<PID>_<AppPool>` instance via `parseW3WPInstance` (BBX-1-11, splits on the FIRST underscore) and matches the object/counter pair. Per-instance `CounterSpec`s use `Field = path` (unique per instance+counter) with `KindGauge`; an aligned `[]iisCounter{key,pid,pool,field}` maps engine output back to `IISWorker` fields — no hot-path string parsing.
- Kinds per packet: ActiveRequests/ActiveThreads/PingLatencyMs all `KindGauge` (nothing here is a rate, so the two-baseline gate has no rate to gate in this group; the engine's gate still applies to any future rate kind, and its valid-status check runs on every reading).
- `Collect(now, dt)`:
  1. `selectedPools()` filters `d.Targets()` to resolved appPool targets only (`Key` prefix `pool:`, non-empty `Pool`, `Start != 0`). Nothing selected → `nil, nil` (owner-selected only; never samples unselected pools).
  2. Re-expand ONLY when `g.changed != nil && g.changed()` (`d.ProcessSetChanged`), via type-asserted `RefreshInstances()` on the same source/query handle, then rebuild specs/engine from `Paths()`.
  3. `src.Collect()` → `engine.Process(now, readings)` → for each emitted field, `matchIISTarget` confirms the instance against a selected target by pool name (case-insensitive, like the resolver) AND PID. The target's `Start` was confirmed by the resolver (BBX-1-11 `matchPool` rejects `Start == 0`), so identity is (PID, creation time) — never PID alone; targets with `Start == 0` are additionally dropped defensively.
  4. One `IISWorker` per matched (pool, PID); fields set only from emitted values — a missing counter stays nil, never 0. Unmatched instances (unselected pool, stale PID after recycle) are omitted. No emitted field at all → `nil, nil` (collector records Missing); a stopped/recycled selected pool has no live instance → no worker, never a zero row.
  5. Workers sorted by (pool, PID) for deterministic output.
- `Close()` closes the source only when the factory created it (`owned` flag); `groupCollector.Close` picks it up via `io.Closer`.
- No goroutine, no ticker, no request text/URLs — pool names + numbers only. One PDH query handle per source, reused for the source lifetime (`PDHSource` contract, pdh_windows.go: "one query handle reused for the source lifetime").
