## What was implemented
Package `blackbox`, pure Go (single import `time`), no Windows API, no goroutine/ticker.
- `CounterKind uint8` with `KindGauge`, `KindRate`, `KindPDHRate`.
- `CounterSpec{Path, Field, Kind}`; `CounterReading{Path, Value, Status, OK}`;
  `CounterSource{Collect() ([]CounterReading, error); Close() error}`.
- `Engine{byPath, history, cores}`; `NewEngine(specs, cores)` clamps cores to >=1.
- `Process(now, readings) map[string]float64`:
  - Valid-status gate on every reading (`OK && Status==0`); invalid readings are
    omitted and never advance the baseline count.
  - Gauge emits `Value` immediately, no clamp (350 on 4 cores stays 350).
  - KindRate/KindPDHRate gated behind TWO valid baselines: samples 1 and 2 emit
    nothing; sample 3 emits the first rate. Per-path history so a late-appearing
    counter starts its own two-baseline count.
  - KindRate: `(Value-prevValue)/dt` vs previous valid sample; dt<=0 guarded (no
    emission, no divide-by-zero); counter reset (`Value<prevValue`) skips emission
    and restarts baselines. KindPDHRate emits `Value` once gated (no delta/reset/dt).
  - One output map per Process; history map allocated once in NewEngine and reused.
  - Absent fields mean missing, never 0. No text captured; paths/fields are fixed ids.

## ONE necessary deviation (open question)
The packet specifies `type Reading struct{...}`, but the package ALREADY defines
`blackbox.Reading` (reader.go:464 — the manifest-read struct, no build tags). A second
`Reading` in the same package is a redeclaration and breaks `go build`/`go vet`, which
the checklist requires to pass. Since the rules forbid touching any other file, the
engine's reading type was renamed to **`CounterReading`**. Every other identifier
matches the packet exactly. This is the minimal change that keeps the build green
without editing reader.go. Flag for packet author: confirm `CounterReading` is acceptable
(or reserve a different name in a follow-up).

## Notes / unconfirmed
- `cores` is held and clamped (>=1) per the packet but is intentionally NOT used to
  clamp or normalize; the multi-core rule is "do not cap at 100", so gauges pass through.
  Reserved for later packets.
- Counter-reset semantics chosen: on `Value<prevValue`, set baselines=1 and treat the
  reset sample as the first new baseline (so the next two valid samples re-gate before
  any rate). `TestEngineCounterResetSkips` asserts no negative rate, skipped emission,
  and that the post-reset sample does not emit.
- Zero-dt guard skips emission and records the latest sample; no division occurs.
