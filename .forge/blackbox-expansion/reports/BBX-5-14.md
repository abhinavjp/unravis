## What was built
**`filestatsSampler.Decode` — per-file I/O stall deltas, ids only.**
- Keys rows by `fileKey{databaseID, fileID}`; keeps only the four cumulative counters as the baseline (`filestatsCumulative`). `size_on_disk_bytes` is a **gauge**: the emitted value is the current one, never a difference.
- **First cycle emits nothing** (`s.prev == nil` → baseline only). A delta with nothing to subtract from is a fabricated number, and "unreadable means missing, never 0" applies to "no baseline" too.
- **New file** (key unseen) is skipped for that cycle — same reason.
- **Counter rollback** (any of the four went backwards: SQL restart, db detach/attach, failover) replaces that file's baseline and emits nothing for it. The next cycle then measures from the new baseline.
- **All-zero deltas are dropped.** An idle file carries no information in a stall series and costs payload; with `TOP 256` the payload is the scarce resource. A payload of nothing for an idle instance is `nil`, not `[].`
- `prev` is **rebuilt from the rows of this cycle** every cycle, so it cannot grow past `CapFileStats`, and files that disappeared (dropped db, truncated tail) stop holding baseline memory. An empty reply clears the map instead of keeping stale baselines.
- No goroutines, no time, no context, no mutex, no driver types, no SQL: deltas are computed in Go, never in SQL (C1/C3 rule from BBX-5-05).

**`agSampler` — AG replica state, only where availability groups exist.**
- `GateID() = "bb:hadr"` → the runner sends `SELECT TOP 1 CAST(SERVERPROPERTY('IsHadrEnabled') AS int)` and skips `bb:ag` when the gate is closed. `bb:ag` reads `sys.dm_hadr_database_replica_states`, which on some editions/views the login cannot see; the gate means that DMV is never touched on an instance that has no AGs.
- `GateOpen` **fails closed**: decode error, truncated, `len(out) != 1`, NULL (edition/platform without AGs), non-numeric value or an unexpected column all mean closed; only `hadr == 1` opens. Closed is not a failure — the runner counts no failure and the back-off is untouched.
- `Decode` emits `[]AG{databaseId, syncState}` (ids + enum). No `replica_server_name`, no `joined_state_desc`, no group ids: forbidden columns are rejected by `decodeRows`, not ignored.

## Open questions / notes for reviewer
1. **Dropped-zero policy**: emitting nothing for an idle file loses the "we saw this file and it did nothing" signal. Chosen for payload; the alternative is a compact `{databaseId,fileId}` presence list.
2. `size_on_disk_bytes` grows monotonically in practice but is a gauge, so it is reported as-is; a db that shrinks shows a smaller value with no delta anywhere.
3. `ag` emits raw `synchronization_state` (numeric enum). Mapping it to a name is a web-layer job (BBX-5-17); the sample carries no text (C9).
4. `bb:hadr` is a control query that runs on the `ag` cadence (60 s), not per tick. If the reviewer wants the gate on the 15 s cadence it must move into the tick prologue, which costs a statement every tick on every instance.
