# Phase 07 rulings on the open questions in phase07-waves.md

Date: 2026-11-03. Maps to section 4 of phase07-waves.md (item 5 maps to section 3 and section 4 question 6; item 6 has no question in section 4).

- **1. Keep running after the last tab closes.** Ruling: add a check that the run loop ends only on Quit, either as an assertion in packet 73e's test (lifecycle_test.go) or as a "close all tabs, process still alive" step in tools/e2e/phase07-smoke.ps1. The owner's answer on this is binding. Why: no packet currently tests it, and main.go has no idle shutdown today. Cost if wrong: a later idle-exit or tab-count change could quit the tray app silently, and nothing would catch it before the gate.

- **2. Locality.** Ruling: tray, installer, shortcut, Startup-folder, single-instance, quit-route and build-script packets stay local (subagents). Only 71a, 76a and 76b may go to the Runner Hub. Why: this is the stricter of the two rules in phase07-waves.md section 4 question 2, and it matches the task rule. Cost if wrong: a hub patch touching Windows objects, shortcuts or the installer would need a full local re-review, and it would still carry a risk of an untested Windows path reaching the tree.

- **3. Extra scope.** Ruling: `--background`, `--quit`, the "Open log folder" tray item, the refusal of an elevated copy, and the ErrNotOurs refusal for a foreign Unravis.lnk are accepted as scope. They must be disclosed to the owner at the end of the phase. Why: they were not in the owner's answers, but they are the implementation of the owner's requests and they ship in the packets as written. Cost if wrong: if the owner rejects any of them, the affected packets (73a, 73b, 73d, 74b, plus the docs in 76a and 76b) must be reworked after the fact, and the acceptance run in 77 would need rerunning.

- **4. Upgrade rewrites an older Startup shortcut.** Ruling: an upgrade or reinstall must rewrite an existing Startup shortcut that lacks `--background`, when the user left "Start Unravis when I sign in" on. This goes into the installer packet that writes the Startup shortcut, which is 74f in phase07-waves.md (its upgrade path is exercised by 74h's tests). Why: this closes the gap in section 4 question 4, where no packet covers the rewrite. Cost if wrong: users who upgrade keep a shortcut that opens a browser at every sign-in, and the sign-in behaviour the owner approved is not what they get.

- **5. Smoke script and pass record.** Ruling: add the optional tools/e2e/phase07-smoke.ps1 for the scriptable manual rows M5, M6, M12, M13 and A7. Add a "Phase 07" section to .forge/investigation-timeline/e2e-pass-record.md with one row per packet id, written at the phase gate and not now. Why: these rows are scriptable, and the script's write scope is not in any packet today, so it needs its own packet entry before its wave runs. The M5 run also needs a way to suppress the default browser, which does not exist yet (section 4 question 6). Cost if wrong: M5, M6, M12, M13 and A7 stay manual, so each phase gate costs a human run, and writing the pass-record section early would record results that do not exist yet.

- **6. Banned hub lanes.** Ruling: battle-sonnet, master-opus and feedback-haiku are banned. They are never to be used for any packet, review or fallback. Why: this is a standing owner rule and applies whatever the delegation table says. Cost if wrong: work goes to a lane the owner has ruled out, which breaks the owner's rule and produces output that was never allowed into review.

- **7. WP-72c event DACL includes the logon-session SID.** Ruling: the WP-72c event DACL includes the token's logon-session SID. The default DACL of the user token grants it full access, and the packet forbids building an explicit descriptor, so the allowlist test permits that one SID. Accepted. Why: the packet forbids an explicit descriptor, and the default DACL is the only way to create the event within that rule. Cost if wrong: another process in the same logon session could signal the stop event. Handed to the Phase 07 Opus security review with the question: "default event DACL also grants the token's logon-session SID full access; the descriptor can't be tightened without an explicit one, which the packet forbids — accept or require an explicit descriptor?". Also for that review: run the 70c launch-code privacy check (launch code never logged or written to disk), which was not run in wave EW2.
