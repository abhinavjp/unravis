## Areas examined with no defect (hub plus own reading)
- File-kind detection (`fileKinds.ts:detectKind`): order is httperr, freb, xe, query store, evtx/event log, error log, then IIS. Names are lower-cased and the folder part is ignored, so `.LOG`, `ex..`, `.log.1` follow the rules; unknown names stay unchosen (a visible "Don't use" note) and content classification is left to the server. The hub and we found nothing. Odd case worth knowing, not a defect: a plain `ex261020.log` (no `u_` prefix) is left unrecognised by design.
- `dropEntries.ts`: reader is called until an empty batch; depth 12 and 1000-file caps set `truncated`; unreadable entries are counted and told. No defect.
- `zipRead.ts` path safety, encryption, unsupported method, deflate size limiter and entry/total ceilings: fine apart from P1.
- XSS / path leakage: all file and host names are rendered by plain interpolation; no `{@html}`, no href/src from names. The only leak is the persisted label (C5).
