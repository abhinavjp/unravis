# Research rulings: per-kind file cards (wizard) and the Add-data card grid (drawer)

Date 2026-11-04. Asked of two remote-hub lanes with the same prompt (no repo, excerpts pasted): droid-az-fw-gpt-6.1-sol-2 (job 37781, "Sol") and droid-az-grok46 (job 37782, "Grok"). Both finished. Merged by the courier; where they disagreed the chosen side is named with a reason. Labels: [S] standard or named pattern (WCAG 2.2, WAI-ARIA APG, GOV.UK file upload, Carbon file uploader, OWASP file upload), [J] design judgement. Nothing here is tested in a browser. Raw answers were kept in the courier scratchpad only.

## Disagreements and what was chosen
- D1 Auto-detect card position: Sol first, Grok last plus a skip link. CHOSEN Sol: first, as a full-width strip above the kind cards. Reason: a stressed user needs the escape route before reading specialist names; it also removes the need for a skip link.
- D2 SQL/Mongo card with no saved connection: Sol keeps it enabled (opening the form fixes it), Grok disables the button. CHOSEN Sol. Reason: wireframes 16 and 28 already exist for "no saved connection yet", so the flow handles it.
- D3 ZIP size and depth: Sol 5,000 entries / 10 GiB / 200:1 server-side, no nesting; Grok 2,000 / 2 GB / 100:1 browser-side, one nested level. CHOSEN Grok's tighter numbers, Sol's no-nesting. Reason: unpacking stays in the browser (zipRead) for now, so smaller caps; nesting is extra risk for little gain.
- D4 Long lists: Sol paginate 50 and avoid virtualising, Grok virtualise over 30 rows. CHOSEN Sol. Reason: keeps focus, find-in-page and screen-reader browse mode predictable.
- D5 Retry: Sol per file plus "Retry N rejected" per card, Grok per file only. CHOSEN Grok for now (current product). Reason: card-level retry risks resending Used files; revisit later.
- D6 Card host/zone default changed after files were added: Sol applies to future files only unless the user opts in, Grok updates only rows still on "Use card default". CHOSEN Grok. Reason: simpler, no hidden state; rows already sent are locked either way.
- D7 Auto-detect regrouping: Sol offers an explicit bulk "apply detected types", Grok never regroups. CHOSEN Grok plus a per-row "Move to {card}" button; no silent regroup. Reason: silent reorder steals focus and confuses.
- D8 Switching card while a batch sends: Sol allows it (queue must live outside the drawer), Grok forbids it. CHOSEN Grok. Reason: ImportBatch aborts its run on leave today; Sol's model needs the queue lifted out of the component (later work, not now).
- D9 Close or Escape with staged items: Sol keeps staging silently and reports on case home, Grok asks before discarding. CHOSEN Grok. Reason: honest and simple; staged File objects cannot survive reload anyway.
- D10 Empty card sticker: Sol "Nothing added", Grok no sticker. CHOSEN Grok (plain text "No files yet" under the title, not a sticker). Reason: empty is normal, not a status.
- D11 Mandatory notice checkbox: Sol says drop it, Grok keeps it. NOT CHANGED: it is in owner-approved screen 112; flagged as an owner question only.
- D12 "Other file": Sol says gate until it has a real purpose, Grok includes it. CHOSEN: include, but it is the same pipeline as auto-detect with the kind select starting at "Unknown"; ask the owner if the two should merge (Q3 below).

## A. Wizard evidence step (screen 37 to 38)
1. DO one shared staging list and one detector behind all cards; cards only pre-set the kind. Reason: separate queues give inconsistent duplicates, settings and results. [J]
2. DO keep the Mongo "Audit export" card (json, csv, zip) although the owner's list omitted it. Reason: screen 37 says audit exports feed steps 2 to 4. Hangfire and Redis importers exist in the tree (fileKindsCopy has hangfire-csv, redis-slowlog-csv), so those two cards are real. [J]
3. DO card order: auto-detect strip; IIS W3C, IIS HTTP error, FREB, Audit export; SQL XE, SQL errorlog, Query Store; Windows events; Application logs; Hangfire; Redis; Other file. Visual order equals DOM order. Reason: step-critical first. [S WCAG 1.3.2; J order]
4. DO cards are NOT exclusive and not a radio group; several cards can hold files. Reason: one incident has mixed evidence. [J]
5. DO markup: step is `section aria-labelledby`, each card a `section aria-labelledby` with its title as heading; related defaults in `fieldset`/`legend`. DON'T use role grid, tablist, or a whole-card button. [S WCAG 1.3.1, 4.1.2; WAI Grouping Controls]
6. DO card anatomy, top to bottom: title; one-line "what it gives"; count text ("No files yet" or "86 files, 1.4 GB"); sticker; defaults (computer name, time zone, only for kinds that need them); Choose files, Choose folder, Guide; file list; Clear this card (when not empty). Reason: purpose, then settings, then action. [J; Carbon]
7. DO two separate pickers per card, never one input that is both `multiple` and `webkitdirectory`; each hidden input is driven by a visible named button; each card is also its own drop target (`aria-label="Drop IIS W3C logs here"`). DON'T make drag the only path. [S WCAG 2.5.7, 4.1.2; GOV.UK]
8. DON'T auto-send on drop or on choose. Files are staged; reading starts on the step's button. Reason: wrong-folder drops under incident stress. [S Carbon review-then-upload; WCAG 3.2.2]
9. DO stickers are text with counts, never colour alone: Ready, Needs computer name (2 files), Needs time zone (1 file), Problem, Reading. Mixed results: "Needs attention: 2 used, 1 rejected". DON'T show a green Ready that hides rejected rows. [S WCAG 1.4.1, 4.1.3]
10. DO Tab order equals visual order, no positive tabindex: step intro, auto-detect, then per card: defaults, Choose files, Choose folder, Guide, file rows (kind, host, zone overrides, include, Remove), Clear this card; then Cancel, Continue. [S WCAG 2.4.3]
11. DO unselect and remove are different, both everywhere. Unselect = per-file "Include" checkbox (maps to the existing "Don't use this file" choice): file stays listed, is not sent. Remove = takes the row out of staging. Per card "Clear this card", global "Clear all" with a confirm only on Clear all ("Remove all 86 files from this step?"). [J; Nielsen error prevention]
12. DO focus after Remove: next row's Remove button, else previous row's, else that card's Choose files. After Clear this card: its Choose files. After Clear all: the auto-detect Choose files. Announce "Removed u_ex261026.log". [S WCAG 2.4.3; J targets]
13. DO one `role="status" aria-live="polite" aria-atomic` region for the step; announce batches ("14 files added to IIS W3C logs"), progress at most every 5 seconds or per card, one summary at the end. DON'T use assertive and DON'T make the result list live. When the run ends, focus the results heading only if the user has not moved. [S WCAG 4.1.3]
14. DO results stay one table (File, Type, Result, Why) as on screen 38, not a table per card. Result words only Used / Partly used / Rejected. Why is quantified ("7,406 lines read, 214 skipped: no time on the line"). [S screen 38]
15. DO Continue is allowed when at least one file is Used or Partly used or the step is empty; rejected files never block. If both IIS W3C and Audit export are empty, warn once (not block): "No IIS logs or audit export. Steps 2 to 4 will have nothing to match. Continue anyway?" [J]
16. DO per-kind guides stay as an in-card disclosure (`aria-expanded`, `aria-controls`), not a modal. Reason: the guide is read while the file is chosen. [S WCAG 4.1.2]
17. DO the wizard unpacks .zip like the drawer (wireframe 37 says ".zip ok"; today the wizard refuses it, which is a gap). Same policy as E5. [J]

## B. Add-data drawer (screen 112)
1. DO open on the five-card grid; order always SQL Server, MongoDB, Blackbox, Files, Another day; native buttons in a labelled list, not a grid role. Title "Add data, case k7m2qx4a"; drilled title "Add files, case k7m2qx4a". [S screen 112; WCAG 2.4.6, 3.2.3]
2. DO real modal: `<dialog>` modal (or `role="dialog" aria-modal` with inert background), visible Close, focus starts on the title (`tabindex="-1"`), returns to the "Add data" launcher on close. [S APG Modal Dialog]
3. DO every drill-in has "Back to Add data"; entering a flow focuses its heading; going back focuses the card you came from. Escape on a form = Back to grid; Escape on the grid = close (with E11 rules). Browser Back mirrors this (pushState while open); no history trap. [S APG; WCAG 2.4.3; J]
4. DO disabled cards stay visible and focusable: use `aria-disabled="true"` plus `aria-describedby` to the on-card reason text; never tooltip-only, never removed from the accessibility tree. DON'T use "Unavailable", "N/A", "None yet" as a reason. [S WCAG 1.3.1, 3.3.2]
5. DO honest copy: SQL/Mongo no connection: card stays enabled, text "No saved connection. Enter details." (D2); connection check failed: "Last check failed. Edit details or check again."; not checked: "Connection not checked" (never "Ready" or "Unreachable" without a check). Blackbox none: "No Blackbox found on this PC. Check again." (found: "1 found here"). Files: "IIS logs, CSV, audit exports (.log, .csv, .json, .zip)". Another day, none: "This case has no source that can be read by day."; some: "3 of 5 sources can be read by day." Any card while a send runs: "An import is already running. Stop it first." [J]
6. DO keep a separate draft per source flow, held above the mounted flow component, so switching cards keeps files, kinds, hosts, zones, exclusions and scroll. The grid shows "Files: 6 staged, not imported". DON'T keep passwords or file contents in browser storage. [J]
7. DO the primary button belongs to the flow on screen only ("Import into this case"); the grid has no primary button, only Close. Other drafts are untouched. Reason: no accidental combined import. [J]
8. DO one import at a time. While files are sending, other cards and Back are disabled with the copy in item 5; Files stays on its list with Stop ("finishes the file being sent"). [J; D8]
9. DON'T auto-close after an import and DON'T jump back to an empty-looking grid: stay on the list with Result, Why, Try again; Done closes to case home, which marks affected steps "Out of date, rerun" (screen 94). [J]
10. DO at 375px (and up to 640px): full-screen sheet, one column, 16px padding, safe-area padding, one scroller, long file names wrap; at 900px and wider a side drawer of at least 480px with a two-column card grid. Test 320px too for reflow. [S WCAG 1.4.10]
11. DO sticky action bar (Back or Cancel, primary) that reserves its own height in the scroller, never hides a focused control or an error, and drops sticky on short viewports or with the on-screen keyboard. [S WCAG 2.4.11]
12. DO targets at least 24x24 CSS px (AA, WCAG 2.5.8); aim for 44x44 on Choose, Remove, Stop. At 375px Choose files / Choose folder are primary and drop is secondary ("Or drop files on this card (desktop)"). [S 2.5.8; J 44]

## E. Edge-case rulings
E1. Same file dropped on two cards: DO keep one staged item and refuse the second add: "Already added under FREB traces." with [Move here] [Keep there]. Match = name + size + lastModified; hash when already computed. DON'T copy it silently or import it twice. [J]
E2. Duplicate on the same card: same name, size and lastModified: not added again, "Already in this list." Same name but different folder or size: add both and show the parent folder on the row (two servers, one file name). Same bytes with a different host chosen needs an explicit "Add as separate source". [J]
E3. File on the wrong card: DO keep it on the chosen card (user intent). The name-guess is shown as "Suggested type", never "Detected". Content wins over the card for the importer: the server rejects with "Rejected: this is a FREB trace, not an IIS W3C log" and a [Move to FREB traces] button; the user changing the row's kind and retrying wins. DON'T auto-move; a row never says Used for the wrong kind. A manual type still cannot bypass schema or safety checks. [J; OWASP validation; matches "server decides unless user changed kind"]
E4. Drop target scope: DON'T use a page-level drop target in the wizard; a drop outside cards adds nothing and says "Drop onto a card, or use Not sure." Intercept file drags only and cancel the browser's default file navigation. Folder on a card: stage its files and one level of subfolders (IIS W3SVC layout), keep relative paths, no folder row, no unbounded recursion; if folder pick is unsupported say so and offer multi-select. [S Carbon explicit zones, WCAG 2.5.7; J one level]
E5. Zips (wizard and drawer, one policy): the card that received the zip owns the inner files (auto-detect card routes by detection); the zip row itself is not sent; inner files keep "bundle.zip / path". Mixed kinds on a typed card: matching files stay, the rest are Rejected with [Move to {kind}]. Refuse before expanding if entries > 2,000, expanded total > 2 GB, or ratio > 100:1, and re-check actual bytes while expanding: "This zip is too large or too compressed to open safely. Unzip it on this PC and add the files you need." Nested zip and password-protected zip: that item Rejected ("Nested zip not opened: unzip it first" / "This zip is password-protected: unzip it on your PC and add the files"), other files unaffected. A zip that breaks a limit or has unsafe paths publishes nothing from itself. Show the first 200 rows with "1,800 more files not listed". Limit numbers are provisional, benchmark first. [S OWASP; J numbers]
E6. Large batches: group per card with counts and a size total ("240 files, 230 ready, 10 need details, 6.2 GiB"), 50 rows per page plus a "Needs attention" filter (D4); required host/zone checks cover hidden rows too. Send one after another in a frozen order (addition order, then path). Show "File 7 of 240, ERRORLOG.1" with an honest phase ("Reading file", no invented percent). Stream or release bytes after each file; never hold all files in memory. Shared failures (disk full, server down) pause the queue, file failures do not. Stop = "Stop after current file"; unsent files stay staged. [S WCAG 1.3.1, 4.1.3; J]
E7. Partial failures: summary in screen 38 voice plus counts: "8 used, 2 partly used, 3 rejected; 3 files added nothing." Continue allowed. Try again is per rejected file only (D5); a Partly used file needs "Choose replacement file", never a blind resend. Mixed card sticker = Problem while any Rejected remains. In the wizard rejected files are not carried into the new case but stay visible on screen 38 and in the review step ("3 files rejected, see why"). In the drawer rejected rows stay with Why and Try again, Used rows stay as a record. DON'T clear failures automatically or replace the list with a toast. [J]
E8. Host and zone: put "Computer name for these files" and "Time zone for these files" on the card (only for kinds that need them: httperr, querystore need host; errorlog and win-events need host and zone; xe and app-log host optional; app-log, Hangfire, Redis zone until the server says otherwise). Each row: "Use card default" or its own value. Changing the card default updates only rows still on "Use card default" (D6); rows already sent are locked. DON'T open a modal per file, DON'T send a host-required file with a blank host, DON'T guess the zone from the engineer's PC. UTC kinds show "Times: UTC". [S WCAG 3.3.2; J]
E9. Auto-detect strip: each row has a Type select (`aria-label="Type for {file}"`) pre-filled with the guess and labelled "Suggested"; after the server reads the file the row says Detected. Failure (empty, unknown, unsupported binary) = Type "Unknown", sticker Problem, Why "Could not detect. Pick a type or remove." Do NOT reject a file just for being binary (xel, evtx are legitimate). No auto-regroup (D7); per-row [Move to {kind}]. Copy "Not sure? Add files and we will check their type" (not a promise to understand everything). [S WCAG 3.3.2; J]
E10. Changing your mind: wizard, any state: Remove and Include both work, even after Used, because no case exists yet (this needs the draft read to be discardable, not a cosmetic row delete). Drawer, not yet sent: same. Drawer, already imported: Remove is disabled with "Already imported. Remove the source from Case home if it should not be in this case."; deleting imported data is a separate Case-home action with an impact note ("Steps that used it will be marked Out of date"), not part of this list. Rejected rows keep Remove and Try again. [J; screen 94]
E11. Navigation: switching cards keeps drafts (B6). Close, Escape or overlay click with staged items: confirm "Leave without importing? 6 files and unsaved fields will be lost." [Keep editing] [Leave] (D9); no confirm when nothing would be lost. While sending: "An import is running. Stop it before leaving? The current file will finish." [Keep importing] [Stop and leave]. Reload: staging is gone, show an empty form, no fake restore; case home is the truth; attach `beforeunload` only while real loss is possible. DON'T retry an import because a response was lost. [S MDN beforeunload, WCAG 3.2.5; J]

## Things NOT to do
- One giant drop zone that guesses later; auto-send on drop; files vanishing into a spinner.
- assertive live regions, or one announcement per file in a 500-file drop.
- Aborting the batch because one file is Rejected; auto-moving files between cards; treating file-name or extension guesses as verified content.
- Colour-only stickers; icon-only or hover-only reasons; nested interactive cards; drag-only folder add; page-level drop that ignores the card under the pointer.
- Remove on an imported row that silently deletes evidence; restoring File objects from storage (not possible, do not fake it); one fake percent across read, send and parse.

## Test checklist (to run, not yet run)
- Keyboard only: choose/cancel files and folders, include/exclude, retype, defaults and overrides, remove first/middle/last row, clear card and all, retry, stop, switch cards, Close/Escape/Back; focus lands as in A12; no hidden tab stops; focus never obscured by the sticky bar.
- Screen reader: NVDA (Firefox, Chrome), JAWS (Edge), VoiceOver (Safari): card names, input names "Choose files", disabled reasons read with the button, indeterminate states, batched announcements, no focus theft at the end.
- 200% zoom and 320/375px reflow: one column, no two-axis scroll, no clipped names or reasons, 24px minimum targets.
- Fixtures: same file on two cards, same name two folders, FREB on the W3C card, mixed zip, nested and password zips, 2,000/2,001 entries, ratio bomb, 500 files, partial results, host/zone missing, auto-detect unknown, Stop mid-batch, Back with staging, reload with staging.

## If you only read one thing
Cards are kind decisions with review-then-send, not twelve uploaders that fire on drop. One staging list behind all cards. The card sets the declared kind; content detection can reject or offer Move, never silently reroute. One file lives on one card. Zips share one capped policy in wizard and drawer. Host and zone inherit from the card until a row overrides. Wizard Used is removable; drawer Used is evidence and is not. Drawer opens on a grid whose disabled cards tell the truth; drafts survive card switches; close asks first; one import at a time; 375px is a full-screen sheet.
