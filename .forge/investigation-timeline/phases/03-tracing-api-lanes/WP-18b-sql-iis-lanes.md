# WP-18b SQL and IIS lanes in the tracing response
risk: high    size: M    wave: 3    model: sonnet

## Outcome
`POST /api/cases/{id}/tracing` returns the `sql` and `iis` lanes built from the saved events of the selected case sources: state, up to 60 events, exact per-bucket counts from the local `GROUP BY` (not capped at 50 000 rows), and the lane metadata `origin:"case"`, `asOf`, `complete`, `truncated`, `reasonCode`, `reason`, `scanned`, `consistency:"stored-as-of"`, plus the top-level `truncated`, `mixedConsistency` and `allLanesStored`. A file whose time zone rule is not confirmed is shown as `clock-unchecked` and plotted nowhere. This packet also defines the two functions phase 04 (WP-17a, the audit lane) calls to add its lane: `appendLane` and `finishTracingMeta`. Covers TR-02, TR-03, TR-04, TR-07, TR-10, TR-18, TR-31, TR-32. New packet: split of spec WP-18 (the route half).

## Write scope
- `internal/server/tracing.go` (adds the functions named below; edits `caseTracing` only to call them)
- `internal/server/tracing_test.go`

## Must not change
- The WP-14 contract block (field names and JSON paths), the WP-14 `tracingSelection`, `tracingRef`, `unwrapCase`, `resolveTracingSources` and the WP-15 axis/validation code. Source resolution (`cs_`/`imp_` ids, the omitted-ids rule, 404 `unknown-source`) is WP-14's; this packet only reads `tracingSelection`.
- `calltrace.BuildLanes`, `laneEvents` logic (WP-13), `casestore` (WP-18a), `caseSources` and `readTraceEvents` in `call_trace.go` (read and reuse `traceRuleValidated`, do not edit).
- The signatures `appendLane(resp *tracingResponse, lane tracingLane)` and `finishTracingMeta(resp *tracingResponse)` once written: WP-17a (phase 04) calls exactly these two, in this order, and adds nothing else to the response meta.
- INV read-only and privacy: no attribute value other than the WP-13 `statusClass` and `win32` is sent; the raw body never contains `client-ip`, `referer` or `cookie:`. No file name leaves the server. No live connection (`h.repo`) is opened here.
- Never assert a millisecond figure in a test.

## Changes
1. Seam for phase 04 (`tracing.go`, exact names):
   - `func appendLane(resp *tracingResponse, lane tracingLane)`: adds `lane` to `resp.Lanes`. If a lane with the same `Key` is already there it is replaced (so calling twice never duplicates). The order of `resp.Lanes` is always `audit`, `sql`, `iis` (rank 0, 1, 2; an unknown key ranks 3, after `iis`), whatever order the calls came in. `resp.Lanes` is never nil afterwards.
   - `func finishTracingMeta(resp *tracingResponse)`: sets, from `resp.Lanes` only, `resp.Truncated` = any lane has `Truncated`; `resp.AllLanesStored` = there is at least one lane and no lane has `Origin == "live"`; `resp.MixedConsistency` = the lanes whose `State` is `events`, `none-seen`, `incomplete` or `out-of-range` carry two or more different `Consistency` values (lanes in state `no-data`, `clock-unchecked` or `disabled` are ignored). It is idempotent and may be called again after another `appendLane`.
   - `caseTracing` (WP-14) calls, in this order: lane builders, `appendLane` once per lane, `finishTracingMeta(&resp)`, `writeJSON`. WP-17a inserts its `appendLane` for the audit lane before the one `finishTracingMeta` call (or calls `finishTracingMeta` again afterwards; both are correct).
2. `func tracingSQLIISLanes(ctx context.Context, c casestore.Case, axis tracingAxis, sel tracingSelection, now time.Time) ([]tracingLane, []string, error)`. `c` is the already unwrapped handle (`caseTracing` passes `unwrapCase(c)`, the same value it gave `resolveTracingSources`). Returns the lanes `sql`, `iis` in that order (both always returned; state `no-data` when nothing is selected for them) and the warnings. Steps:
   - Selected imports: `recs, err := c.Imports(ctx)`; `refByImport map[int64]tracingRef` is built from `sel.Refs` in request order using `sel.ImportOf` (first ref wins when a tag and an `imp_` id name the same import; import id 0 means a tag with no file yet and adds the one warning `"A selected source has no file yet, so it shows nothing."`). Keep only records in `refByImport` with `Status == casestore.StatusOK` or "". Records whose `calltrace.LaneOf(Importer)` is not `sql` or `iis` are dropped with the one warning `"A selected source is not an SQL or IIS source, so it is not shown."` (once per request). `sel.AuditIDs` is ignored here (WP-17a).
   - One `calltrace.SourceInfo` per kept record: `Name` = importer, `Validated` = `traceRuleValidated(record)`, `From`/`To` = the quality coverage (as `caseSources` does, `call_trace.go` lines 276-286), and the WP-13 fields `SourceID` = the `refByImport` id, `Label`.
   - Window rule (deliberate): tracing is START-BASED and half-open, `[axis.Start, axis.End)`, with NO lookback. This differs from `/call-trace`, which widens the read by `callTraceLookback` (30 minutes, `call_trace.go:34`) to catch a statement that began before the call; the tracing view plots an event where it starts, so a statement that began before the window and overlaps it is not shown. State this in the doc comment of `tracingSQLIISLanes`.
   - Events: one `c.Events(ctx, casestore.EventQuery{Window: importer.Window{From: axis.Start, To: axis.End}, Sources: <validated importer names of both lanes>, Limit: casestore.MaxEventQuery})`; drop events with `Start` at or after `axis.End` (the store window is inclusive, tracing is half-open). Skip the read when no validated source exists. `calltrace.BuildLanes(calltrace.Window{From: axis.Start, To: axis.End}, true, infos, evs)`, keep the `sql` and `iis` lanes only. If the read returned `casestore.MaxEventQuery` events, apply `calltrace.MarkIncomplete` and set `truncated:true`, `reasonCode:"rowcap"`, `reason:"Only the first 50,000 saved events were listed; the bucket counts cover every saved event."`.
   - Limitation (documented in the doc comment and in the test): `EventQuery.Sources` filters by importer NAME, and an `evidence.Event` carries no import id, so when an unselected import of the case has the same importer name as a selected one, its events can appear in `events[]` of that lane. Bucket counts stay exact, because they filter by `ImportID`. Consequence for the numbers: `scanned` is the sum of the bucket counts and so counts SELECTED imports only; in this same-importer case the lane can list more events than `scanned` (listed events may include an unselected import's). State this in the doc comment of `tracingSQLIISLanes` and in the comment of the second sub-case of `TestTracingUnselectedImportNotCounted`; no code change.
   - Buckets: package var `var tracingCountBuckets = casestore.CountBuckets` (a seam for the test). Per lane with at least one validated import and no unconfirmed clock, call `tracingCountBuckets(ctx, unwrapCase(c), casestore.BucketQuery{AxisStart: axis.AxisStart, From: axis.Start, To: axis.End, WidthMs: axis.WidthMs, Sources: <that lane's validated importer names>})`. The `unwrapCase` is mandatory: a `*sharedCase` hides `casestore.BucketCounter`, and without it `CountBuckets` silently falls back to the 50 000-row scan (same pattern as `case_sources.go:185`). Add a count only when its `ImportID` is 0 or is in `refByImport`. Emit one bucket per `axis.Bucket(k)` with `ok`, zero-filled, fields `start`, `end`, `count`, `clipped`, `complete:true`; `errors` stays nil (the key is omitted, WP-14 contract). `scanned` = result `Total`.
   - Metadata: `origin:"case"`, `consistency:"stored-as-of"`, `asOf` = latest `Imported` time (UTC, RFC 3339) among the lane's selected imports (`now` when none), `complete:true`, `truncated`/`reasonCode`/`reason` as above, otherwise `false`, `""`, `""`. `sources` = the lane's `SourceRefs` as `{sourceId, label}`. Events are mapped from `LaneEvent`: `id`, `sourceId`, `label`, `start`, `end`, `durationMs`, `severity`, `statusClass` (WP-13), `win32`; `hidden` as given.
   - Unconfirmed clock: any selected import of the lane with `Validated == false` gives `state:"clock-unchecked"` (from `BuildLanes`), `disabled:"tz-rule"`, `buckets:[]`, `events:[]`, `reason:"The time zone rule of a file is not confirmed, so its events are not placed on the timeline."`, `reasonCode:""`, and no `CountBuckets` call for that lane. The lane's validated imports are not plotted either (same rule as `/call-trace`).
   - Ambiguity: when two selected imports share an importer name, events of that name get `sourceId:""` (WP-13) and the warning `"Events from <importer> cannot be tied to one source because two selected files use it."` is added once per name. Bucket counts stay exact per import.
3. `caseTracing`: after the WP-14/15 steps call `tracingSQLIISLanes`, then `appendLane` for each returned lane, set `resp.Warnings` (the selection's warnings plus these; never null), call `finishTracingMeta(&resp)`. Errors go through `writeStoreError` (a canceled request answers 400, as `/call-trace`). Note: the IIS "time-end" uncertainty (`w3cTimeIsEnd`) is closed by WP-20, which stores each request at its logged timestamp; this packet adds no time-end warning and counts by event start.

The window in these tests is 2026-03-10 10:00-11:00 UTC.

   - `TestTracingClockUnchecked` (function level, `stubTraceCase` of `call_trace_gaps_test.go:20`; its only import is an `iis-w3c` `ImportRecord` with `ID` 1, `Status` `casestore.StatusOK`, `TZRule` "" as `call_trace_gaps_test.go:98-100` builds it; the sql lane has no import, so no bucket query runs and the stub's nil `Each` is never reached): lane `iis` state `clock-unchecked`, `disabled` `tz-rule`, empty `buckets` and `events` (`[]`, not null), exact `reason`; lane `sql` state `no-data`.
