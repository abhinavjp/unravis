# WP-17b Stacked three-lane tracing chart
risk: medium    size: M    wave: 4    model: sonnet

## Outcome
The timeline shows one stacked row per lane (API audit, SQL, IIS) on one shared UTC floor-aligned time axis. It draws exactly the buckets the server returned (no summing, no estimates), says in plain words why a lane is missing or partial, shows the non-dismissable "collected at different times" note, and labels the real bar width (TR-04, TR-10, TR-16, TR-31 look, INV-1, INV-2).
Split of spec WP-17 (reported to the caller): 17a is the Go audit read, 17b is the web chart.
Size: this is the upper bound of M (four files, one pure module, one component, one test). If a run overflows, finish `lanes.ts` and its test first, then the component; do not drop the keyboard selector (WP-61 needs `onSelect`). Hover/focus text (TR-22) is deliberately not here: WP-17c adds it.

## Changes
Note: the wire carries one series per lane (`buckets`: `{start, count, errors?}`; the client model defaults a missing `errors` to 0). The prototype also draws comparison-period rows, 4xx/5xx splits, HTTP.sys and blocking panels; those are not in this packet and not in the lane contract, and phase.md lists them as accepted deviations. Panel titles below are the prototype's where the data supports them. Types (`TracingResponse`, `TracingLane`, `TracingBucket`, `TracingWindow`, `TracingLaneKey`) come from `../tracing/model` (WP-16a). The axis is the SERVER's: `response.window` carries `start`, `end`, `axisStart`, `axisEnd` and `bucketSeconds`; the chart never recomputes the axis from the request window.
1. `web/src/lib/tracing/lanes.ts` (pure, no Svelte, imports only types from `./model`):
   - `LANE_ORDER: TracingLaneKey[] = ['audit','sql','iis']`; `LANE_NAME = { audit: 'API requests (audit log)', sql: 'Database (SQL Server)', iis: 'Web server (IIS)' }`; `LANE_ASK = { audit: 'Was the application slow or failing?', sql: 'Were database calls slow, blocked or failing?', iis: 'Were web requests slow or failing before reaching the app?' }`.
   - `PANEL_TITLE = { audit: 'How many requests, and how slow they were', sql: 'Slow database calls (over 1 s) and failed calls', iis: 'Web-server requests (errors shown darker)' }`.
   - `LANE_STATE_TEXT` for `no-data`, `none-seen`, `clock-unchecked`, `incomplete`, `out-of-range` (copy of `callTraceCopy.ts`): `'This case has no file for this source'`, `'Files cover this time and nothing was seen'`, `'Time zone not checked, so nothing is drawn'`, `'Read hit its limit; events may be missing'`, `'Files do not cover this time'`.
   - `INCOMPLETE_TEXT = { timeout: 'The audit read ran out of time; nothing was shortened.', rowcap: 'The audit read reached its row limit; nothing was shortened.', error: 'The audit read failed; nothing was shortened.' }`.
   - `MIXED_NOTE = { title: 'Some data was collected at different times.', body: 'API data was read just now, while SQL and web-server data came from saved logs. Compare the timing and trends, but do not expect totals from the different sources to match exactly.', fixed: 'This note cannot be dismissed.' }`.
   - `TRUNCATED_NOTE = 'The list of events was cut at its limit. The counts in the bars are not affected.'`.
   - `interface SlotGrid { firstMs: number; widthMs: number; n: number; windowStartMs: number; windowEndMs: number }`; `slotGrid(window: TracingWindow): SlotGrid | null`, built only from the server's axis: `widthMs = window.bucketSeconds*1000`, `firstMs = Date.parse(window.axisStart)`, `n = ceil((Date.parse(window.axisEnd) - firstMs)/widthMs)`, `windowStartMs`/`windowEndMs` = `Date.parse(window.start/end)` (used only by `slotOutside`). Returns null when a time is not finite, `axisEnd <= axisStart`, `bucketSeconds <= 0`, `n < 1` or `n > 2000` (the server's series cap). No floor/ceil of the request window is done here: the server already floored the axis to UTC multiples of the width (INV-1). WP-61 reuses `slotGrid` and `slotStartMs` for the hand-off, so keep them exported with these exact names.
   - `slotLeftPct(g, i)` = `100*i/g.n`; `slotWidthPct(g)` = `100/g.n`; `slotOutside(g, i): boolean` (true when the slot starts before the window or ends after it); `slotStartMs(g, i)`.
   - `interface Bar { index: number; count: number; errors: number }`; `barsFor(g: SlotGrid, buckets: TracingBucket[]): Bar[]` (one bar per returned bucket, `index = floor((startMs-firstMs)/widthMs)`. Floor, not an exact-multiple test: the server clips a bucket's `start` to the request window (WP-14 contract, WP-15 `Bucket(k)`), so the first bucket can start inside its cell, for example at 10:07:30 in the 10:07:00 cell; a bucket start that does not parse, or an index below 0 or at/above `g.n`, is dropped; two buckets with the same index add their counts and errors; it never invents a bucket); `barMax(bars): number` (0 when none).
   - `widthLabel(seconds): string`: under 3600 -> `'N minute(s)'`; up to 86400 -> `'N hour(s)'`; singular for 1.
   - `axisCaption(zoneName: string, bucketSeconds: number, hasOutside: boolean): string` = `'Time (' + zoneName + '). Each bar covers ' + widthLabel + ', starting at the time on its left edge; every panel uses the same time axis. '` + (bucketSeconds > 60 ? `'Longer periods group more time into each bar so the chart stays readable. '` : `''`) + (hasOutside ? `'Grey dashes are slots outside your window.'` : `''`).
   - `laneNote(lane: TracingLane): string`: `''` for `events`; for a lane with `disabled` set (`"tz-rule"`) the lane `reason` when non-empty, else `LANE_STATE_TEXT['clock-unchecked']` (a disabled lane draws no bars); for `incomplete` the lane's own `reason` when non-empty, else `INCOMPLETE_TEXT[incompleteReason]`, else `LANE_STATE_TEXT.incomplete`; for the other states the lane `reason` when non-empty, else `LANE_STATE_TEXT[state]`.
2. `web/src/components/TracingChart.svelte`. Props: `{ response: TracingResponse; zone: string; selected?: number | null; onSelect?: (slotIndex: number) => void }`. The grid is `slotGrid(response.window)` computed once per response; when it is null the component shows the lane notes only and no bars. Imports `formatTime` from `../lib/time` (`formatTime(ms, { zone, precision: 'minute' })`), `timeZone` is passed in by the parent (`timeZone.zone`), never read here. Markup, in order:
   - If `response.mixedConsistency`: `<div role="note" class="notice">` with `MIXED_NOTE.title` (bold), `MIXED_NOTE.body`, `MIXED_NOTE.fixed` (muted). No close button.
   - Lanes are drawn in `LANE_ORDER` (look each up by `key` in `response.lanes`; a lane the server omitted is skipped). One grid, four columns: lane label, left axis, panel, right axis (`grid-template-columns: auto 3.5rem 1fr 3.5rem`; at 375 px the label sits above the panel and the axes stay inside the panel width). Each lane row shows: a colour swatch from `var(--lane-audit|--lane-sql|--lane-iis)` (defined once on the `.tracing-paper` root by WP-16b, light and dark; this component defines no colour variables and uses no fallback of its own), `LANE_NAME[key]` as the heading, `LANE_ASK[key]` as small text, and a one-line origin tag: `Read just now` for `origin==='live'`, else `From saved logs`, plus `lane.asOf` formatted with `formatTime`.
   - Panel: title `PANEL_TITLE[key]`; for `events` (or `incomplete` with at least one bucket), and never when `lane.disabled` is set, draw one absolutely positioned `<div class="bar">` per `Bar` from `barsFor`: `left: slotLeftPct`, `width: slotWidthPct` minus a 1 px gap, `height: count/barMax*100%`; a darker `<div class="bar-err">` inside it with height `errors/count*100%`. Left axis ticks `0` and `barMax`; right axis stays empty in this packet. Slots outside the window get a short grey dash under the axis. For `none-seen` draw the empty panel with the text `No events in this period`. For `no-data`, `clock-unchecked`, `out-of-range`, a lane with `disabled`, or `incomplete` with no buckets, draw no bars and show `laneNote(lane)` centred in the panel. An `incomplete` lane that has bars also shows `laneNote(lane)` as a bad-tone `role="status"` line under the panel, so a partial read is never mistaken for a full one.
   - Shared axis row under the last panel: about six tick labels (every `ceil(n/6)` slots) from `formatTime(slotStartMs, ...)`, then a caption `<p class="axcap">` = `axisCaption(zoneName, response.window.bucketSeconds, anySlotOutside)`. `zoneName` is `UTC` when `zone==='UTC'`, else the zone string.
   - When `response.truncated` (server-derived: true when any lane is truncated): a footnote `<p class="foot">` with `TRUNCATED_NOTE` under the caption. A lane with `lane.truncated` also carries `data-truncated="true"` on its row (WP-17c reads it for the lane tooltip).
   - Bucket selector overlay over the panel column: `<div role="group" aria-roledescription="bucket selector" aria-label="Time buckets. Left and right arrow keys move, Enter opens Run analysis for the selected bucket." tabindex="0">`; ArrowLeft/ArrowRight move a local selection within `0..n-1`, Enter calls `onSelect(index)`, click on a column selects it and calls `onSelect`. A visible 2 px focus outline; the selected slot is highlighted. (The Run-analysis hand-off itself is WP-61.)
   - Colours come only from CSS variables; bar widths never use fixed pixel counts; the chart never asserts anything about timing.
3. `web/src/components/TracingPaper.svelte`: in the `chart` region's `ready` branch replace the plain lane list by `<TracingChart response={result} zone={timeZone.zone} />` (import `timeZone` from `../lib/timeZone.svelte`; import `TracingChart` statically: both are already inside the lazy `TracingPaper` chunk). Do not touch the loading/error branches, and keep WP-16b's empty-case branch (`TRACING_TEXT.emptyNoSources` when `sources` and `lanes` are both empty): `<TracingChart>` is rendered only when that branch is not taken.
4. `web/tests/tracingChart.test.cjs` (load `.ts` through the `ts.transpileModule` loader helper used by `web/tests/casehome.test.cjs`; read `.svelte` as text). Tests:
   - `slot grid comes from the server axis`: a window object with `axisStart` `2026-10-01T00:00:00Z`, `axisEnd` `2026-10-31T00:00:00Z`, `bucketSeconds` 21600 gives `n === 120` and `firstMs % 21600000 === 0`; `axisStart` `2026-10-01T00:00:00Z`, `axisEnd` `2026-10-31T08:00:00Z` (a window sent as 00:01 to 00:01) with 28800 gives `n === 91`; a one-hour axis with 60 gives `n === 60`; a request window `10:07`-`11:07` with axis `10:00`-`12:00` at 60 s gives `n === 120`, `slotOutside(g, 0)` true and `slotOutside(g, 30)` false (the grid follows the axis, not the request window); reversed axis, `bucketSeconds` 0, a non-date string and `n > 2000` give `null`.
   - `bars are exactly the returned buckets`: on the 60 s axis `10:00`-`12:00`, four buckets: one at `10:07:30` (clipped start, inside the 10:07 cell), one at `10:08:00`, one at `09:00:00` (before the axis) and one with start `"x"` give two bars with indexes 7 and 8 and the given counts and errors, and an empty slot gets no bar; two buckets in the same cell add up; `barMax([])` is 0.
   - `lane wording is verbatim`: `LANE_STATE_TEXT`, `INCOMPLETE_TEXT`, `MIXED_NOTE`, `TRUNCATED_NOTE` and `LANE_NAME` equal the strings above; `laneNote` of an `incomplete` lane with reason `''` and `incompleteReason: 'rowcap'` returns the row-limit sentence; a lane with a server reason returns that reason; an `events` lane returns `''`.
   - `axis caption names the real width`: 3600 s in UTC contains `Each bar covers 1 hour`; 21600 s contains `6 hours` and the "Longer periods" sentence; 60 s does not contain "Longer periods"; `hasOutside` adds "Grey dashes".
   - `disabled and truncated lanes`: `laneNote` of a lane with `disabled: 'tz-rule'` and reason `''` returns the `clock-unchecked` sentence; the component text contains `lane.disabled` and `data-truncated`.
   - `chart component is plain, read-only and keyboard operable`: `TracingChart.svelte` contains `aria-roledescription="bucket selector"`, `ArrowLeft`, `ArrowRight`, `Enter`, `role="note"`, `MIXED_NOTE`; has no `from '../lib/charts'`, no `echarts`, no `guided`, no `callTrace`; contains no `dismiss`, no `response.bucketSeconds` and no `--lane-audit:` definition (the colours are WP-16b's).
