# WP-17a Audit lane: one bucketed read per source
risk: high    size: M    wave: 4    model: sonnet

## Outcome
The tracing handler gets its audit lane from one server-side `$match`+`$group` aggregation per source on the UTC floor-aligned grid, never from raw rows, and a failed or over-budget read becomes `complete:false` with reason `timeout`, `rowcap` or `error` instead of a short or silent window (TR-04, TR-10). Split of spec WP-17 (reported to the caller): 17a is the Go read, WP-17b is the web chart.

## Changes
Verified in code: `audit.RollupReader` is `Rollup(ctx, plan audit.RollupPlan) (audit.RollupSlots, error)`; `RollupPlan` has exported fields `SourceIDs []string; From, To time.Time; Zone string; Loc *time.Location; SlowMs float64; Width time.Duration`, so a plan can be built directly with `Zone:"UTC"`, `Loc:time.UTC`, `SlowMs: audit.DefaultRollupSlowMs` and `Width` set to the READ width `readW` = `min(W, 1 h)` where W is the presented width `time.Duration(axis.WidthMs)*time.Millisecond` (the slot expression `rollupSlotExpr(plan.Width)` floors Unix seconds by `Width`, i.e. aligns to the epoch, not to `axis.AxisStart`; that equals the axis grid only when `Width` divides 3600 s, which holds for every rung up to 1 h and for the 1 h read width; for W of 2 h or more the read uses 1 h slots and Go folds them into the axis cells, step 2). `Store.Rollup` does one aggregation per source, takes the 10 s budget for windows up to `audit.LiveRollupMaxWindow` (24 h) and the 60 s budget above it, and returns `ErrBroadScanRefused` above 24 h unless the process runs with broad scans allowed (`store.WithBroadScans`). A failed source is listed in `RollupSlots.Sources` with `OK=false` and `ErrorCode` (`query_timeout`, `query_memory_limit`, `query_failed`, `permission_denied`, `connection_failed`) and adds no slots.
Note: the spec says "existing broad-scan gate". In code a window over 24 h on the audit lane works only when the server was started with broad scans allowed; otherwise the lane must say so (see step 2), never shorten the window.
1. `internal/server/tracing_audit.go`. Types:
   - `type auditBucket struct { Start, End time.Time; Clipped bool; Count, Errors int64 }` (UTC, one per AXIS cell, produced by the fold in step 2; `Start`/`End`/`Clipped` come from `axis.Bucket(k)`; `Errors` is the 5xx count `RollupCounts.C5xx`).
   - `type auditLaneRead struct { Buckets []auditBucket; Complete, Truncated bool; Reason, ReasonCode string; AsOf time.Time; Scanned int64; Sources []audit.SourceResult }` (`ReasonCode` is one of `timeout`, `rowcap`, `error` or empty; `Reason` is the plain sentence; `Truncated` is always false because counts are aggregates).
   - `func readAuditLane(ctx context.Context, reader audit.RollupReader, sourceIDs []string, axis tracingAxis, now func() time.Time) auditLaneRead`. `AsOf = now()` taken before the read starts. The plan is `From=axis.Start`, `To=axis.End` (half-open, already validated by WP-15), `Width=readW`, `Zone:"UTC"`, `Loc:time.UTC`.
2. Behaviour of `readAuditLane` (one `reader.Rollup` call; if `reader` is nil return `Complete=false`, `ReasonCode="error"`, `Reason="The audit source cannot be read here."`):
   - Success: read `slots.Builder.Wire()`. FOLD each wire slot into an axis cell: `k = (slot.Start - axis.AxisStart.Unix()) / (axis.WidthMs/1000)` (integer floor; a slot start before `axis.AxisStart` cannot occur because the plan starts at `axis.Start >= AxisStart` and hour slots are hour aligned, but if `k < 0` or `k >= axis.Buckets` drop the slot and still count it in `Scanned`), then `from, to, clipped, ok := axis.Bucket(k)`; skip when `ok` is false. Sum `Counts.Total` into `Count` and `Counts.C5xx` into `Errors` of the cell (several slots share one cell when W is 2 h or more; for W of 1 h or less it is one slot per cell). Emit cells in start order with `Start=from`, `End=to`, `Clipped=clipped`. Bucket starts therefore equal the SQL/IIS cell starts of the same response, whatever W is. `Scanned` = sum of `Counts.Total` over all slots. `Complete=true` only when every entry of `slots.Sources` has `OK=true` and the slice is non-empty.
   - Some sources failed: keep the buckets of the sources that worked (the store already adds nothing for failed ones), `Complete=false`, `ReasonCode` from the first failed source: `query_timeout` -> `timeout`; `query_memory_limit` -> `rowcap`; anything else -> `error`. `Sources` carries the per-source results.
   - Whole-call error: no buckets, `Complete=false`. `errors.Is(err, context.DeadlineExceeded)` or `audit.ErrDocsExaminedBudget` -> `timeout`; `errors.Is(err, audit.ErrRollupGroupLimit)` or `errors.Is(err, audit.ErrLimit)` -> `rowcap`; `errors.Is(err, audit.ErrBroadScanRefused)` -> `error` with `Reason = "The audit source reads at most 24 hours unless broad scans are allowed, so this window was not read."`; context cancel is returned as-is by setting `Reason=""` and `ReasonCode="error"` (the handler drops a cancelled request); everything else -> `error`.
   - Plain sentences (copy verbatim): timeout `The audit read ran out of time; nothing was shortened.`; rowcap `The audit read reached its row limit; nothing was shortened.`; error `The audit read failed; nothing was shortened.` Never put a raw error text, connection string or source name into `Reason`.

LISTING FAILURE RULE (the single definition; WP-14 refers here): `h.repo` is never nil in production, and a nil `h.repo` is treated like an empty source list. Only the cells that have data are listed (zero-fill is not done here; the client fills the grid, WP-17b).
