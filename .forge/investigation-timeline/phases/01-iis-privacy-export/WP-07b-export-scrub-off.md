# WP-07b Case export with scrubbing turned off
risk: high    size: M    wave: 4    model: sonnet

## Outcome
The case export honours `scrubSensitive`: with scrubbing on (the default) the file carries no `client-ip`, `referer` or `cookie:*` attribute; with it off the file carries them in a checked, reduced form, and its masking statements say so (TR-15, TR-22). The verifier accepts both variants and still rejects a file that carries an address, link or query text outside those three attributes.

## Write scope
- `internal/evidence/caseexport.go` (edit `CaseInput`, `exportEvents`, `caseStatements`, `BuildCase`; add the sensitive policy)
- `internal/evidence/caseexport_verify.go` (edit `verifyCase`, `verifyStatements` callers, `verifyEvents`)
- `internal/evidence/caseexport_test.go` (add tests; no existing test edited)
- `internal/server/case_views.go` (edit `buildCaseExport` and its two callers; about 6 lines)
- `internal/server/case_export_scruboff_test.go` (new; one test, step 10)

## Must not change
- `exportPolicy`, `exportDropped`, `ExportAttrNames` and `ExportPolicyKeys` contents: the sensitive attributes live in a separate map, so the fix5 drift test (`TestFix5ExportPolicyCoversEveryImporter`) sees no change from this packet.
- The findings export (`internal/evidence/build.go`, including the "Left out by default" line at `build.go:158`): it has no scrub option.
- Existing assertions: `caseexport_test.go:83` (`ev[4].Attrs["cookie"]` is not on any allowlist and stays out) and `TestBuildCaseNoIPsOrUserIDs` (`caseexport_test.go:320`) stay green and unedited.
- INV-3: a raw cookie value, server IP, query string or user agent is never written, even with scrubbing off; only values that pass the shape rules in step 2 are kept, anything else becomes `[removed]` (the existing `removedText`).

## Changes
1. `CaseInput` gains `IncludeSensitive bool` (doc comment: false is the default and drops `client-ip`, `referer` and `cookie:*`). `BuildCase` passes it to `exportEvents` and `caseStatements`. Zero value keeps today's output byte for byte except for the statement in step 4.
2. `caseexport.go`: add `var exportSensitivePolicy = map[string]map[string]attrPolicy{"iis-w3c": {...}}` plus `func sensitivePolicyFor(source, key string) (attrPolicy, bool)`. Use the existing `attrPolicy` type with a new rule `ruleSensitive` and a `sensitive string` field naming the shape: `client-ip` keeps a value that `netip.ParseAddr` accepts without a zone, else `removedText`; `referer` keeps a value that starts `http://` or `https://`, has no `?`, `#`, `@`, space or control character, and is at most 256 bytes (`MaxEventAttrValue`, the limit `verifyEvents` enforces; the importer already stores at most 256), else `removedText`; any key `cookie:<name>` with `<name>` matching `^[a-z0-9_.-]{1,64}$` keeps a value matching `^[0-9a-f]{32}$`, else `removedText`; a `cookie:` key with any other name is dropped. Add the case to `exportAttr` and `attrValueOK`. Only `iis-w3c` has this map.
3. `exportEvents(key, events, w, includeSensitive)`: for each attribute, use `exportPolicy[ev.Source][k]` first; when absent and `includeSensitive` is true, use `sensitivePolicyFor`. When `includeSensitive` is false these three are skipped exactly as an unlisted attribute is today. `verifyEvents(events, includeSensitive)` resolves the policy the same way through one shared helper `policyFor(source, key string, includeSensitive bool) (attrPolicy, bool)` so builder and verifier cannot drift.
4. `caseStatements(w, includeSensitive)` (today `caseStatements(w caseWithholding)` at `caseexport.go:749`; the first element of its slice is the headline). Three constants, with exactly this text (ASCII, no digits, no `@`, no `://`, so `scrubText(s) == s`, `residualRisk(s)` is false and `claimFree(s)` is true; the word "because" is banned: `LintCausal` in `copylint.go:18` rejects cause, because, due to, led to, resulted in, root cause, proof, proven and similar, and "since" is not in `causalRe`):
   - `scrubOnStatement` = `Client IP addresses, referers and cookie digests are not in this file.`
   - `caseHeadlineScrubOff` = `This file holds the imported events and import summaries of one case. File names, file hashes, raw host names, URLs and paths, query and SQL text, user agents, messages, raw user names and source line numbers are not in it. Each imported file is named by its importer only.` (the current first statement without "IP addresses, " and without "cookies, referers, ")
   - `scrubOffStatement` = `This file holds client IP addresses, referers and cookie digests since scrubbing was turned off. They come from the IIS web server log (W3C) only; client addresses of the HTTP error log are not in this file. Cookie values are digests, never raw values. Server IP addresses and query strings are not in this file.`
   When `includeSensitive` is false: the slice is unchanged except that `scrubOnStatement` is inserted right after the first statement. When true: the first statement is `caseHeadlineScrubOff` and `scrubOffStatement` is inserted right after it. The statement count stays below `maxStatements` (32); `scrubOffStatement` is far below `maxStatement` (2048).
5. `verifyCase`: set `scrubOff := contains(e.Manifest.Masking.Statements, scrubOffStatement)`; pass it to `verifyEvents`. The existing whole-file checks (`claimFree`, `@`, `://`, `ipv4`) keep running on `raw` when `scrubOff` is false. When true, run the `@`, `://` and `ipv4` checks on the JSON encoding of a copy of the export whose events have the three sensitive attribute kinds deleted; run `claimFree` on `raw` in both cases. A file with scrub-off events but no `scrubOffStatement`, or with the statement but a `scrubOnStatement` too, fails with `caseInvalid("scrubbing statements disagree")`.
6. `case_views.go`: `buildCaseExport(w, r, c, scrub bool)` takes the resolved bool; set `in.IncludeSensitive = !scrub`. The request fields are `*bool` (WP-06a: `ScrubSensitive *bool`, and `caseExportPreview(w, r, raw string, scrub *bool)`; `func resolveScrub(p *bool) bool` returns `p == nil || *p`). So `caseExportPreview` calls `buildCaseExport(..., resolveScrub(scrub))` and `caseExportConfirm` calls `buildCaseExport(..., resolveScrub(body.ScrubSensitive))`. A field that is absent or JSON `null` means scrub ON (TR-21: ON by default). Nothing else changes in that file.
7. Size: M upper bound (4 files; the `case_views.go` edit is about 6 lines, so the packet is not split). Note: WP-06a's preview id already includes the scrub flag, so a confirm sent with the other flag meets 409 before this code runs.
8. Note: the importer does not store these attributes until WP-02b and WP-03 merge. These tests build events by hand, so they do not wait for them. If `TestFix5ExportPolicyCoversEveryImporter` fails after WP-03 because `client-ip`, `referer` or `cookie:*` are allowed importer attributes, WP-03 adds them to `exportDropped["iis-w3c"]`; do not add them to `exportPolicy`.
