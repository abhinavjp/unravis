## MAJOR

[MAJOR] WP-17a Changes 2-3 (default audit-lane behaviour undefined and self-contradicting) — WP-17a:30 says the audit ids are "all audit sources of the case when `sourceIds` was omitted or empty; the ids are the ones WP-14 kept in `auditIDs`", but WP-14:32 defines `AuditIDs` as "the audit ids as sent (empty when `sourceIds` was omitted)" and WP-14:36 says "No audit id is added". Then WP-17a:30 says "When `auditIDs` is empty ... do not add an audit lane". Result: the default call (WP-16b sends no `sourceIds`; the UI never sends audit ids) never gets an audit lane, so the main screen shows no audit data and the wire lane order promised in WP-18b:20 is never exercised end to end. The packet also says nothing about an audit id the case does not know (WP-14 passes any non-`cs_`/`imp_` id through unchecked, 404 applies only to `cs_`/`imp_`). — Fix: in WP-17a step 3 state the rule: when `sel.AuditIDs` is empty and `sourceIds` was omitted or empty, resolve the audit ids as every source the live repository lists (`h.repo.ListSources`-style call used by the audit source list; if `h.repo` is nil, no audit lane); when explicit audit ids were sent, pass them as they are and let `RollupReader` report an unknown id through `slots.Sources[i].OK=false` (lane `complete:false`, `reasonCode:"error"`), never a 404. Add a test `TestAuditLaneDefaultsToAllSources` in WP-17a step 4. If the intent is "omitted = saved sources only", say so in WP-14:36 and WP-16b instead and drop the "all audit sources" sentence.

[MAJOR] WP-17a Changes 3 (stale against the WP-18b seam) — WP-17a:30 tells the implementer to "insert [the audit lane] at index 0 of `lanes`", to call `finishTracingMeta` "on the whole slice", to "re-read the end of the handler and keep its single call", and uses a variable `width`. WP-18b:20-22 defines `appendLane(resp *tracingResponse, lane tracingLane)` (replace-by-key, forced order audit, sql, iis) and `finishTracingMeta(resp *tracingResponse)` (takes the response, idempotent), and WP-15 keeps the axis as `axis tracingAxis` with `WidthMs`. There is no `lanes` slice and no `width` variable in the handler; a workhorse model will either STOP (its own STOP clause) or invent structure. phase.md:25 and :45 already promise WP-17a uses exactly `appendLane` then `finishTracingMeta`. — Fix: replace the middle of WP-17a step 3 with: "call `appendLane(&resp, auditLane)` after the existing `appendLane` calls for sql/iis and before the one `finishTracingMeta(&resp)` call (or call `finishTracingMeta(&resp)` again afterwards; it is idempotent). Use `axis.AxisStart`, `axis.AxisEnd`, `time.Duration(axis.WidthMs)*time.Millisecond` as the width, and `axis.Start`/`axis.End` as `from`/`to`. Do not edit `appendLane`, `finishTracingMeta`, `tracingSQLIISLanes`." Drop the "index 0" and "whole slice" wording and the "single call" instruction.

[MAJOR] WP-17a Changes 1-3 vs WP-15 axis (audit buckets misalign for width of 2 h or more) — the audit read is `RollupPlan{From: from, To: to, Width: W}` (WP-17a:24) and the rollup slot expression floors Unix seconds by `Width` (`internal/audit/rollup.go` slot expression; `RollupBuilder` keys by `floor(ts / Width) * Width`). The WP-15 grid is `[AxisStart + k*W, ...)` with `AxisStart` floored to the hour only. For `W` in {1 h, 60..900 s} the two grids agree (all divide 3600). For `W` of 2, 4, 6, 8, 12, 24 h, `floor(unix/W)*W` is aligned to the epoch, not to `AxisStart`: e.g. window 10:07-11:07 never reaches this, but a 30-day window starting at an odd hour with `W = 6 h` or `8 h` (WP-15 phase proof: 8 h/91 buckets) puts audit slot starts up to `W - 1 h` away from the SQL/IIS cells; the first slot starts before `AxisStart` and WP-17b positions by `floor((start - axisStart)/width)`, which is negative, so the first audit bucket is dropped or lands in the wrong cell. R6-02 ("aligned UTC axis") requires all lanes on the same grid. — Fix: in WP-17a make `readAuditLane` always ask the rollup for 1 h slots (`Width = time.Hour`; for `W < 1 h` use `W`), then fold them in Go into axis cells: `cell = floor((slotStart - axis.AxisStart) / W)`, `Start = max(axis.AxisStart + cell*W, axis.Start)` (clipped as WP-18b buckets are), summing `Count` and `Errors`. Add `TestAuditLaneAlignsToAxis` (window starting at an odd hour, W = 6 h, assert every audit bucket `start` equals a SQL/IIS bucket start for the same window and the bucket count sums are unchanged). Keep the single `reader.Rollup` call.
