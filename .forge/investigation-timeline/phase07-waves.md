# Phase 07 background-run: execution waves (35 packets, 8 waves + 1 closing step)

Source: plan.md §3 rows, each packet's Write scope, delegation.md, model-allocation.md, runner-hub.md. Planning aid only; plan.md §3 stays the dependency authority.
Plan §3 has 9 global levels. This schedule compresses to 8 by delaying three off-critical-path packets (74b to EW3, 73d and 75b to EW6) and by running WP-77 as a closing step after the docs unit. Critical path: 70a, 70c, 70d, 73a, 73b, 73c, 73e, 76, 77 (every step edits `cmd/audit-explorer/main.go` in turn).

Rules used
- Write scopes: no two packets share a file inside one global level (check-plan shows 0 overlaps). Shared files are always in different waves (`main.go` 70c, 70d, 73a, 73b, 73c, 73e; `plan.go` 74f, 74h, 75b; `uiserver.go` 74g, 74j; `os_windows.go` 75a, 74e, 75c).
- Stricter rule added here: one unit per Go package per wave (a half-edited sibling file breaks `go test ./pkg` for the other agent). Packets of one package in one wave are one unit, run in the order listed. If units run in separate git worktrees this rule can be relaxed.
- Executor key: `L-S/h` local Sonnet high, `L-S/m` local Sonnet medium, `L-H` local Haiku low, `Hub:` Runner Hub lane. HIGH risk packets also get the Opus security review at the phase gate. Tray, installer, shortcut, single-instance, quit-route, build-script packets stay local (task rule) even where delegation.md would allow droid-sonnet-5.
- Every returned hub patch is applied in a scratch worktree, checked against the packet Write scope, and proof-run locally before use.
- `go` = `.dev\toolchains\go\bin\go.exe` from repo root, env of WP-58 step 3. `lx` = `$env:GOOS='linux'; go vet <pkg>; Remove-Item Env:GOOS` -> no output.

  - No console window (M12): PE subsystem 2 (70f) plus no `conhost` child after start. Scriptable.
  - Port taken (M6): hold the port with a TcpListener, start, assert exit 1 and a `#32770` window titled "Unravis could not start" (FindWindow). Scriptable.
  - MCP spawn (M7): already automated by 70f. Log hygiene (A7): `Select-String <log> "launch\?c="` empty. Scriptable.
  - Tray icon (M2-M4): semi-automatic with UI Automation on the notification area (find button "Unravis", Invoke, count new browser tabs); fragile on Windows 11 overflow, so keep a human tick. Explorer restart (M3) is VM only.

## 4. Open questions and contradictions

1. Keep running after the last tab closes: only phase.md and WP-76a (docs) say it. No packet adds a test or an M row for it. `main.go` has no idle shutdown today, so behaviour is probably right; add one assertion (a 73e test that the run loop ends only on quit, or a smoke step "close all tabs, process still alive").
2. Hub rule conflict: delegation.md sends every non-gated sonnet packet to droid-sonnet-5, but the task rule keeps tray, installer, shortcut and startup work local. This schedule follows the stricter rule, leaving only 71a, 76a and 76b on the hub. Also delegation.md lists 20 high packets "including 73c, 74b..." and omits 73e; 73e is `risk: high` and stays local.
3. Owner list vs packets, extras the owner did not name: `--background` flag (73a), `--quit` flag (73a), tray entries "Open log folder" and a hidden "Start at sign-in" for dev builds (73d), refusal of an elevated copy and "another account" message (73b, 73a), and ErrNotOurs refusal for a foreign `Unravis.lnk` (74b). Confirm these are accepted as owner scope.
4. Sign-in setting: matches the owner answers (checkbox default ON already true in `web/setup/App.svelte` and `silent.go`; shortcut is the single source of truth in 74b, 74h, 74i). One gap: a Startup shortcut made by an older install has no `--background`, so it opens a browser at sign-in until an upgrade or the tray toggle rewrites it; 74b `TestEnableReplacesAnOlderShortcutOfOurs` covers rewrite, but no packet says upgrade rewrites it when the user left the setting on.
5. Quit and Desktop shortcuts: "Quit Unravis" Start-menu entry (74f) and Desktop shortcut for the installing user (74f, 74j) match. For a just-for-me install with an elevated worker the window writes them after commit (74j), so a crash between commit and the window write leaves an install without them (repair brings them back; fine, but M9 should say so).
6. Pass-record and automation: WP-77 is the only place the manual rows live and it does not own a script. Decide whether to add `tools/e2e/phase07-smoke.ps1` as an extra packet (write scope not in any packet today) or leave M5, M6, M12, M13 manual. The open signal starts the default browser (rundll32), so an automated second launch needs a way to suppress or stub the browser; none exists.
7. `--version` and `--mcp` stay in the same exe: 73b runs the gate after the `--mcp` branch and `--version`, and 70f proves both over pipes; but no 73b test names that order (only `TestMainSkipsTheGateWithNoBrowser`), so the 70f re-run after 73b/73c/73e is the real guard.
