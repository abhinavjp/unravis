## Behaviour

- First screen: demo goes straight to running (port 18770 flow untouched). Locked key goes to unlock. A deep link or a resumed tab investigation goes to running. Otherwise start. A status that cannot be read is treated as "no key" for routing.
- Illegal moves are ignored and logged with `console.warn` in dev only (never any typed text).
- Home (header) goes to start and does not close the case; filters, zoom, ledger and drawer history are not touched. Leaving the working screen puts the side panel away; the case stays open on the server. Closing a case in the case panel now also returns to start.
- A 423 from any case route calls `signalCasesLocked` and the app shows the unlock screen, remembering where to return to after the right key.
- Locked key: start screen shows no titles or counts and never requests the case list.
- Master key (I5): the passphrase is a local component variable, read into a local constant and cleared before the request, sent only in the setup/unlock body, never put in a URL, header, storage, console or error. `MasterKeyApiError` uses fixed text. Tests assert this on the API calls and on the component source.
- Unlock: one field, one button, Enter submits, field cleared after every attempt, refocused after a failure, `autocomplete="off"`, type password. Wrong key, throttled and network failures show the same sentence; throttled only adds the wait.

## Deviations

1. New Landing mode is named `cases`, because the existing mode `start` is the "Run analysis" welcome state and is kept.
2. Added a "Go to the analysis" link on the start screen. Without it, live users (sources already connected, no deep link) would have no way to reach the connect prompt or analysis now that start is the first screen.
3. The autorun effect is gated on `screen === 'running'`, so the start and unlock screens never start a query.
4. The unlock/start/setup/home/lock header entries hide the analysis controls on non-running screens.
5. `ImportPanel.svelte`: the case intent is applied right after the existing `selectedId` line (not inside it), and `goHome` has its own import line, so the existing importJob.test greps stay valid.
6. Home is hidden in demo.

## Concerns

- A network failure on unlock shows the wrong-key sentence (as the packet says). A person with a dead server sees "not the master key", which can mislead.
- `GET /api/cases` has no source count, so rows show imports only. `caseCounts` supports `sources` when the list route later sends it.
- Opening a case from the start screen goes to the working screen with the import panel open on that case; the autorun starts if saved sources exist. Focus return after that panel opens may be lost because the card button unmounts.
- Screen changes add no browser history entries (Back leaves the app as before).
- First-run users with no sources now land on start, then reach connect via "Go to the analysis".
- `StartScreen` makes its own status read in addition to the one in `initialize`; the second is cheap and keeps the screen self-contained when reached via Home.
- The setup form clears both fields on any attempt, including a refused one, so a person retyping after "too short" starts over.
- Screen `create` is unreachable until `WIZARD_READY` is set.
