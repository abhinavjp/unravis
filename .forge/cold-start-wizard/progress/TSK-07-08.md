## Routes (all need the session token and a local Origin, like every `/api` route)
Common errors, body `{"error":"<reason>","reason":"<message>"}` shape is the existing `caseFailure`:
- 401 missing/wrong token; 403 foreign Origin; 405 wrong method.
- 400 bad JSON or unknown field (shared `decodeJSON`).
- 404 `case-not-found`: malformed id and missing id answer identically.
- 409 `case-closed` on any write to a closed case (reads still work).
- 422 `bad-tag` (empty/too long/control or bidi chars/bad classification), `tag-cap-exceeded` (33rd env, 201st source).
- 503 `tags-unavailable` if the store has no Tagger.
- Errors never echo input.

SourceTag JSON (`sourceTagDTO`): `{"id":int,"importId":int,"kind":str,"label":str,"env":str,"portal":str,"api":str,"classification":str,"created":RFC3339}`. `importId` 0 means none.

1. `GET /api/cases/{id}` -> `{"id","title","created","closed","bytes","imports", "envs":int, "sources":int}` (the existing case fields plus counts from the opened case's `Info()`).
2. `GET /api/cases/{id}/environments` -> `{"environments":["prod","staging"]}`.
3. `PUT /api/cases/{id}/environments`, body `{"environments":[...]}` -> `{"environments":[...]}` (trimmed, blank dropped, case-insensitive dups collapsed, order kept; `[]` clears; max 32, 60 chars each).
4. `GET /api/cases/{id}/sources` -> `{"sources":[SourceTag,...]}` oldest first (never null).
5. `POST /api/cases/{id}/sources`, body `{"importId":int,"kind":str,"label":str,"env":str,"portal":str,"api":str,"classification":str}` -> 201 with one SourceTag. `kind` required; max 200 sources; fields max 80 chars (env 60).
   - Text that looks like a connection string or password (`mongodb://`, `mongodb+srv://`, `://user@`, `password=`/`pwd:`...) -> 422 `bad-tag`.
   - If `kind` is `"mongo-database"` (TSK-08): `classification` must be `audit`|`other`|`unused` else 422 `bad-classification`; `label` must be a database name from a recent successful `/api/connections/test` else 422 `database-not-tested`. Re-posting the same label and env replaces the earlier row.
6. `DELETE /api/cases/{id}/sources/{sourceId}` -> 200 `{"removed":true,"eventsDeleted":false,"message":"..."}`. Imported events are never deleted. Bad/zero source id -> 404 `source-not-found`; an id that no longer exists still answers 200 (store semantics).
7. `GET /api/cases/{id}/mongo-sources[?classification=audit|other|unused]` -> `{"sources":[SourceTag,...]}` only `mongo-database` rows of that classification; default `audit`; any other value -> 400 `bad-classification`.

Server-side test record: names only, last 8 successful tests, 30-minute TTL, in memory, never persisted; no connection string is kept.

## Deviations
1. `server.go` edited (one field, one line). Required by TSK-08 change 1; allowed as "the file that holds testConnection".
2. Delete route is `/sources/{sourceId}` (the packet named DELETE without an id). New matcher `caseSourcePath`.
3. `sharedCase` (the gate wrapper) hides `Tagger`; `tagCaseOf` unwraps to the inner Case before asserting. Tag writes take the read share, so they do not wait for imports.
4. Classified databases are stored as `kind:"mongo-database"` with `label` = database name; `portal`/`api` stay free.
5. Order of checks in `postSource`: Mongo classification, then `CleanSource`, so a bad classification on a Mongo row answers `bad-classification`; on other kinds an invalid classification is `bad-tag`.
6. "Case migrated from v3 shows zero counts" is covered with a fresh case on both stores; the migration itself is covered by TSK-06 tests.
7. `getCase` was added to the existing `/api/cases/{id}` route (it previously had DELETE only).
