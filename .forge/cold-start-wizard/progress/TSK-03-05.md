### Route
`POST /api/discover/scans/{scan}/findings/{finding}/locate`

- Allowed method is POST only. Other methods get 405 with `Allow: POST`.
- The session token (`X-Audit-Token`) is required, and the local Origin/Host checks apply as for the other routes.
- The route works on any `log-file` or `log-set` finding, including a demoted one. Any other kind gets 409 `not-locatable`.

Request: `{"path": "D:\\Apps\\Orders\\Logs"}`. The path may be a file or a folder. A folder is read one level deep and no directory listing is ever returned.

Response 200:
```json
{"verified": true,  "files": 3, "reason": "", "finding": { ...the updated finding, verified:true, importer set... }}
{"verified": false, "files": 0, "reason": "not-found|cannot-open|empty-file|wrong-format|no-log-files|timed-out"}
```
`finding` is present only when `verified` is true. A verification failure leaves the stored finding unchanged. A repeated call gives the same answer.

Other responses use `{"error": "...", "reason": "..."}`:
- 400: reason is `path-not-absolute`, `path-not-local` or `path-unsafe`. The message is generic and never echoes the input.
- 401 for a missing token, 403 for a bad origin.
- 404: `scan-unknown`, `scan-expired` or `finding-unknown`.
- 409: `scan-not-ready` (scan not done) or `not-locatable`.
- 429 when the rate limit is hit: 30 charged calls per minute. Refused paths do not use the allowance.

### Security properties
- Local-only: the real FS refuses non-fixed drives (`path-not-local`).
- Confined: `Final` plus `Lstat` reject reparse points and any canonical-name mismatch (`path-unsafe`). UNC paths, device prefixes, `..`, ADS, control characters, secret words, value shapes and paths over 1 KiB are refused.
- No directory listing and no input echo, checked by tests.
- The ids in the URL are opaque. The path goes only in the body.
- Work runs under a 10 s budget and gives `timed-out` when the file system stalls.

### Exported names for TSK-18 and TSK-19
From `web/src/lib/discover.ts`:
- `Finding` now has `verified: boolean`, `unreadable: string` (a wording key, empty when none) and `suggest: Suggestion | null`.
- `Suggestion` is `{ portal: string; api: string }`.
- `isSelectable(finding)` is true only for a file kind with an importer and `verified === true`.
- `readinessLabel(finding)` gives the plain-language reason for a file kind that is not selectable, and `''` otherwise.
- `locateFinding(scanId, findingId, path, signal?)` returns `Promise<LocateResult>`.
  - `LocateResult` is `{ok: true, files, finding}` or `{ok: false, files, reason: LocateReason}`.
  - A failed check and a 400 refusal are both results. An expired scan, a 429, a lost connection or an unreadable answer throw `CaseApiError`.
  - An empty path or one over `MAX_LOCATE_PATH` (1024) comes back as a result with no call. A bad id throws `bad-finding-id`.
- `LocateReason`, `LOCATE_FAILURES`, `LOCATE_REFUSALS` and `MAX_LOCATE_PATH`.
- `probeReachable(host, port, signal?)` returns `Promise<ProbeResult>`.
  - `ProbeResult` is `{reachable, reason}`, and `ProbeReason` is `refused|timed-out|no-such-host|blocked|''|unknown`.
  - A bad host or port throws `CaseApiError` `bad-host` or `bad-port` with no call.
  - A 400, 429 or lost connection throws.
- `PROBE_REASONS`.

From `web/src/lib/copy/discoverCopy.ts`:
- `unreadableText(key)`, `locateReasonText(code)` and `probeReasonText(code)`. Unknown input gives a general plain line, never a raw key.

## Deviations
1. `internal/discover/verify.go` gained `LogFileOK` and `SuggestNames` as well as `VerifyPaths`. The packet named only `VerifyPaths`.
2. `internal/server/routes_test.go` has a new row. This was an accepted edit.
3. The wrappers live in `discover.ts`, not `api.ts` or `types.ts`. `send`, `json` and `CaseApiError` are in `cases.ts`, `Finding` is in `discover.ts`, and `api.ts` is the separate audit-query client.
4. The 30-per-minute locate rate limit is new. The other discover routes have none, but the packet asked for a limit.
5. Locate works on any log-file or log-set finding, including demoted ones, because no naturally pathless log4net finding exists (the applog detector emits a Gap). Tests plant a synthetic one.
6. Locate failure codes are a closed set of short codes, not wording keys, so `wording.go` and its golden file are untouched. The web copy maps each code to words.
7. `LogFileOK` accepts `.txt` and similar extensions as logs, as `logExtRe` does.
