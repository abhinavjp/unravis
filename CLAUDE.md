# Unravis (api-audit-explorer)

- Finish what you start (owner rule, 2026-11-12): the owner tests with LIVE data, never dummy data. A feature is done only when it works on the real data path end to end. Never ship a UI that is demo-only and then ask the owner for input before doing the real part. If a real-data step needs something unknown (field names, a shape), find it yourself first through the app's own read-only code, safe sources and the repo; ask the owner only when that is truly impossible, and ship everything else in the same pass. Never end a turn with "not implemented yet" or "waiting for X" when part of the work can be built now. When a slice has a demo path and a real path, build both before reporting; say plainly what is verified on live data and what is not.
- Shared backlog and checklist: `docs/BACKLOG.md` (owner rule, 2026-11-12). Every chat adds new items there, and ticks an item only when it works on the real data path. Items under "Backlog (deferred)" are not to be built without the owner's go; today that means anything that needs a new collector or agent.
